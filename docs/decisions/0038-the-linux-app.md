# 0038 The Linux app: one Go binary with GTK and WebKitGTK, a StatusNotifierItem tray, and freedesktop notifications as a native push device

Date: 2026-11-20 · Status: **accepted** (#461) · The counterpart of 0037 (the Mac app) · Builds on 0007 (the module), 0028 and 0030 (the owner socket, sessions), V0.mac-shell and V0.mac-notify (the Mac app's window and its native push device, whose protocol this app speaks)

**Context.** On a Linux desktop Fyr was a PWA or a Chrome `--app` window from `fyr open -app`: a browser's window with the browser's Web Push, and nothing in the tray. The Mac gets a native shell (0037). Both desktops should behave alike, and the rules of what notifies must not be written twice.

**Decision.**

| Question | Decision |
|---|---|
| The shell | `cmd/fyr-desktop`: one Go binary, cgo with GTK 3, WebKitGTK 4.1 and Ayatana AppIndicator. Its logic is `internal/desktop` (pure Go, tested without a display); the GTK side is a thin preamble in `shell.go`. A build without cgo is a stub, so `CGO_ENABLED=0` (CI, `make`, the release) builds and vets the repository as before. Tauri/wry was not taken: a Rust toolchain and a second dependency tree for a window, a tray and a D-Bus call |
| What notifies | fyrd decides, as for every device: the app is a native push device (V0.mac-notify), the same protocol as Fyr.app. It stores itself with `POST /push/native` on the owner socket, keeps its endpoint in `~/.config/fyr/desktop.json` so its settings survive restarts, and reads `GET /push/native/stream`; a 404 there (the device was removed) stores it again. Presence, quiet hours, what the device hides and whether it wants finished threads all apply in fyrd; the shell applies no rule. It reconnects after fyrd restarts or updates itself |
| Settings in the window | The shell answers the page's `fyrPush` bridge (WebKitGTK's script message handler with a reply, the same calls as WKWebView's): `status`, `on`, `off`, so the bell, the test, hidden projects and finished threads work as on a phone. It adds `clear` ({threadId, state}): the page's `clearThreadNotification` closes the app's notification of a thread that moved on, as it closes the service worker's in a browser. Only a page on Fyr's origin gets an answer. The window registers no service worker |
| Notifications | `org.freedesktop.Notifications` over GDBus: one per thread (a newer notice replaces the thread's older one, as Web Push's topic does), urgency normal (low for a finished thread; never critical, which passes Do Not Disturb), the default action opens `/?open=<host>/<thread>` in the window, an `ActivationToken` lets Wayland focus the window |
| The window | A WebKitGTK view on `http://fyr.localhost:PORT` (WebKitGTK resolves it with no exception, unlike WKWebView). It keeps its cookies in `~/.local/share/fyr-desktop/web`, so a start loads the app with the session it has; only a main-frame 401 asks the owner socket for a one-time link, at most once in 30 s, and the signed-out page is not shown then. A load that fails while fyrd answers (it moved to another port) signs in again. External links (a new window, or a click off Fyr's origin) open in the default browser; a Fyr page in a new window opens in a child window. The size is restored (`~/.config/fyr/desktop.json`). Files drop into the composer as in any WebKit view. Ctrl+W hides, Ctrl+Q quits, Ctrl+R reloads. While fyrd does not answer it shows a page saying so, and loads Fyr again when fyrd is back. Its user agent ends in `FyrDesktop/linux`, so Settings → Devices calls its session "The Fyr app on Linux" |
| Tray | A StatusNotifierItem (Ayatana): Open Fyr, Open in Browser (a one-time link in the default browser), the unit's state, Pause or Resume, Show Log (`daemon.log`), Quit. GNOME shows it with the AppIndicator extension; KDE, Xfce, Cinnamon, sway and Hyprland bars show it as they are. Closing the window keeps the app in the tray; starting it again shows the window (GtkApplication `io.github.meros.Fyr`, one instance) |
| Pause and Resume | `systemctl stop` and `start` of `fyr.service`, the system unit that runs as the owner on both installs (the module, and `scripts/install-linux.sh`). Not a `systemd --user` unit, as #461 assumed: both installs make a system unit. With `services.fyr.desktop.enable` polkit lets the owner start, stop and restart that unit and nothing else, without a password; elsewhere polkit asks |
| Registration | On NixOS the module owns the unit; the app starts nothing and shows its state. Elsewhere a unit that is installed but disabled is enabled and a stopped one started when the app starts (opening the app is asking for Fyr); a unit nobody installed is left to the install |
| Packaging | Not a Flatpak: its sandbox would need holes for the owner socket, `~/.local/share/fyr`, `systemctl` and the log, which is the whole app. Not an AppImage: WebKitGTK bundles badly and the distributions ship it. The flake's `fyr-desktop` package (binary, `.desktop` file, icon), installed by `services.fyr.desktop.enable` with an autostart in the tray (`-background`). On other distributions the binary needs the distribution's GTK 3, WebKitGTK 4.1 and libayatana-appindicator; a release asset built on the self-hosted runner and installed by `install-linux.sh`, and an update offered by fyrd as 0037's "Update Fyr.app" is, come in a later change |

**Consequences.** The two desktops share the push device, its rules and settings, the sign-in and the web client's bridge; each shell is a window, a tray and a notifier. fyrd is unchanged: its self-update, Web Push and the phone work as before, and the app follows fyrd's restarts and updates by itself. `go.mod` is unchanged (the shell's libraries are C, from the distribution). The cost is a cgo binary outside the cross-compiled release until the runner builds it per architecture, and a tray that GNOME hides without its extension (the window and the notifications work without it).
