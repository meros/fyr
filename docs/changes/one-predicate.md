# V0.one-predicate: "an open PR that counts" and "a PR that waits on CI" are one predicate each, every reader of a Condition walks it the same way, and a quota notice missed on a clean run end has its own invariant ID

→ V0.185 and V0.203 (snooze and settle when done), V0.settle-merge-fixes (2), V0.quota-wait-midturn, V0.thread-invariants-recent-bugs.

(1) **One predicate for an open PR.** "The thread has an open PR that counts" was written five times and they disagreed: the settle check, the work that goes on (which also counted pending checks), the "Waiting for CI" line (which also asked for a read), the next main PR, and the main PR "Settle when merged" is offered on. The last one did not leave out a PR the owner marked done or that was abandoned, so "Settle when merged" was offered on a main PR that the settle check did not count as open. Now `Change.OpenPR` is the one predicate (GitHub shows it open, and it is not dismissed, done or ended) and `Change.PRWaitsOnCI` the other (an open PR whose checks Fyr read as running). A PR never read waits on nothing, as the "Waiting for CI" line already said: a repo with no CI, or a PR Fyr cannot read, must not hold a snooze or a wait for ever. The snooze until work is done used to wait on such a PR until its first read.

(2) **One walk through a Condition.** The readers of a Condition's structure looked at different branches: `anchored` and the stale-watch check skipped `Not`, the snooze's `workBound` looked only in `Any`, the settle's `doneBound` only in `All`. And the scheduler skipped every thread Rule that reads `workDone`, but only the owner's "settle when done" fired at the end of the reduce, so another Rule on `workDone` inside an `All` never fired (the same held for view Rules on `workOver` and the snooze). Now `When.walk` is the one walk (the node, then `All`, `Any` and `Not`), and `anchored`, `anchor`, `anchorPR`, `nextCheck`, `changeOf`, `workBound` and `doneBound` use it. The end of the reduce fires every thread Rule that reads `workDone` and every view Rule that reads `workOver`. The stale-watch check stays the Condition's logic, not a walk: a `Not` of a Condition that can no longer hold is true from then on, which fires rather than waits.

(3) **Small ones.** The engine reads `Thread.Asleep` where it spelled out settled or archived. `FyrEffectFor` reads a map by ask, built once; two effects with one ask stop the program at start.

(4) **Its own invariant ID.** The engine's check of a clean `run.ended` whose summary opens with a quota notice reported core's `thread-quota-misclassified`, so that ID's meaning lived in two files. It is now `thread-quota-missed-on-end`, defined in the engine. The two thread invariant files are layers (core reads the record; the engine reads the run's Inputs and timing) and stay two.
