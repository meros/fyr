# V0.pr-switcher-height: the PR tab's switcher keeps its height on a phone, so a thread with several PRs can still pick one

→ V0.multi-pr (5). *Fixes V0.multi-pr's PR tab switcher on the phone.*

(1) **The bug.** A thread that tracks several pull requests shows them as pills in a strip above the PR tab ("PRs (3)"), and a pill picks which PR the tab shows. On the phone the strip vanished whenever the PR was longer than the pane, which is most PRs with a description: it was a row of the tab's column flex box with `overflow-x: auto` set on it (the pills scroll sideways), and a flex row with a scroll container as one of its own axes has an automatic minimum size of zero. With the content shorter than the pane nothing had to give; with content taller, the column squeezed the strip to 0 px and the only way to reach the other PRs was the header chips. The desktop wrapped instead and kept its height, so the two fronts differed.

(2) **The fix.** The strip never shrinks (`flex: none`) on both fronts. The phone keeps its one scrolling line (`flex-wrap: nowrap; overflow-x: auto`), the desktop its wrapped pills. Nothing else about the switcher changes: the order (open first, then merged and closed until dismissed), the repository prefix when the PRs span repositories, and the pill's status word.

(3) **Covered.** `?mock=1&open=t_stack&tab=pr` is a thread with a stack of four PRs across two repositories, each with a long body, so the PR tab scrolls; the layout test opens it on both fronts and checks that the switcher, its pills and the selected pill's words are there and that every pill is a 44 px target. The layout test's target list skips elements of height 0, which is how a strip squeezed to nothing passed before; the new check reads the strip itself, and it fails (0 px at every size) with the rule removed. The pills are left out of the tab's "past the right edge" measure there, since the phone scrolls them sideways on purpose, as V0.host-tabs does for the host tabs.
