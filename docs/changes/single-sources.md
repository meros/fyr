# V0.single-sources: the live view's bridge has one source file, and tests that slept or read source text check behaviour instead

→ V0.37 (the bridge and TestMockBridgeMatches), V0.119 (3), V0.145, V0.149, V0.187, V0.196 / V0.autoclose-clock, V0.load-invariants, V0.thread-invariants. No behaviour of the app changes.

The bridge every live view page starts with was written twice, once in Go and once in the client's mock, and a Go test compared the two texts. Five layout checks waited a fixed time instead of for the state they check, one of them timing "Saved" against the wall clock. Two unit tests matched JSX, labels and an object literal's layout in the source, so a refactor that kept the behaviour failed them, and a broken behaviour with the same text passed.

1. **One bridge.** `web/viewbridge/bridge.html` is the bridge. The Go package `web/viewbridge` embeds it (`viewbridge.HTML`), and `internal/engine` puts that in every view page. `web/src/mock.ts` imports the same file as text: esbuild's text loader in `scripts/build.mjs`, and for the unit tests `test/text-loader.mjs`, a Node module hook that `npm test` loads with `--import`. `src/text-imports.d.ts` types the import. TestMockBridgeMatches is removed. The bridge's behaviour is still tested by TestViewBridgeGivesPressFeedback (Go) and by the layout test's V0.37 and V0.165 sections, which drive the mock's bridge, now the same file. Proof: a bridge that always answers "failed" fails `V0.37 desktop: the pressed button gives no Sent feedback`.
2. **"Saved" runs on a fake clock.** Its timer moved from the hook into `src/saved.ts` (`savedClock`, `SAVED_MS`), and `useSaved` uses it. `test/saved.test.ts` checks it on node:test's mock timers: shown at a save, still shown at 1999 ms, gone at 2000 ms, restarted by a second save, and dropped when the page closes. The layout check V0.119 (3) now only waits for Saved to go. Proof: a 2300 ms mark and a timer that is not restarted each fail the unit test, and a mark that never goes fails `V0.119 desktop: Saved never goes`.
3. **No fixed sleeps in five layout checks.** Each now waits for the state it checks, and each was shown to still fail with the behaviour broken (built, run with `FYR_SECTIONS`, reverted):
   1. V0.187 waits for the hovered Copy to reach opacity 1. With the hover rule removed: `Copy does not show on hover`.
   2. V0.next-step-chips waits for the opened chip's card. With the card's class changed: `the opened chip null` on both fronts.
   3. V0.196 / V0.autoclose-clock waits until both clocks' own animations have run 3 s. The check now compares where each clock ends (its start on the animation timeline plus its length, as wall time) with the deadline, instead of the time left against the harness's wall time. Reduced motion is turned off before the press, so the clock starts when the section opens. The old form failed under load, because the clock started only when reduced motion was lifted, which the old comparison counted as drift. With `HideClock`'s length read on every render (the bug it guards): `clock ends -3277 ms after the section closes`.
   4. V0.145 used to wait 1.5 s to see that waiting adds no history entry. Now the stream (the mock's `__fyrThread` hook) renames the open thread and one in the list, the check waits until both names show, and only then counts the entries. With a thread update that pushes an entry: `an entry added while nobody opened a thread`.
   5. V0.119 (3): see 2.
4. **Behaviour in place of source text.** The test that both fronts draw invariant cards (it matched `inbox.tsx`, `phone.tsx`, `invariants-ui.tsx` and the Settings labels) is now a layout section, `V0.load-invariants desktop|phone`. With `?invariants=1` the mock has a broken load invariant and a broken thread invariant (`withInvariants`, `mockInvariantCommand` in `mock-load.ts`). The section checks that the two cards are under Needs you, newest first, each with Fix it and Dismiss (44 px on the phone). Dismiss (desktop) and Fix it (phone) must send their command with the card's id and close the card, and Settings → Automation must list Load invariants and Thread invariants. Proof: the desktop's cards drawn under Working, Dismiss sending the Fix command, and the phone's cards drawn under Working each fail it. In `api-capabilities.test.ts`, the match of `api.ts`'s object literal became a call: `createApi("")`, `"?mock=0"` and `"?mock="` give an Api with mock false, cache true and pushes true. Proof: `cache: false` in `api.ts` fails it. The lint-like check that the shell never reads `api.mock` stays.
5. **No raw fetch anywhere in the client.** The check of `http.test.ts` that only `http.ts` calls `fetch(` now covers every `.ts`/`.tsx` file in `web/src` except `http.ts` and `sw.ts`. It found none. Proof: a probe file that calls `fetch("/a")` fails it.
