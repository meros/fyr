# V0.agent-env: an agent process never inherits a credential or endpoint variable from whoever started fyrd

→ Amends V0.50 (2), V0.53 (2), #167. Every agent process starts with fyrd's environment plus what its provider's adapter sets. Until now fyrd's environment kept whatever credentials and endpoint variables it was itself started with: `launchenv.Scrub` removed only the four `FYR_*` variables that name the live install (#167). So a stale `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` or key in the daemon's environment reached the agent, and the adapter's own value was appended after it as a duplicate. A process whose environment resolves duplicates last-wins then talks to the inherited endpoint instead of its provider's, or to the inherited account instead of a Claude account that should have passed no endpoint at all.

(1) **The names.** `cli.CredentialVars` (`internal/cli`) is the one list: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, the five `ANTHROPIC_*MODEL` role variables, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_SUBAGENT_MODEL` and `CLAUDE_CONFIG_DIR`. The adapter sets each one a provider needs (V0.50 (2)), so none has to be inherited; a value Fyr does not set is a value the provider does not have.

(2) **Where it is applied.** `launchenv.Without(env, names)` drops named variables; `Scrub` is `Without(env, Names)` and keeps its meaning. The base environment of an agent process is `Without(os.Environ(), …CredentialVars)` at all four launch sites: the session process (`internal/claude/client.go`), the print runs (`claudecli.Print`), the model-list probe (`claudecli.Models`), and the CLI login (`internal/provider/login.go`, which `claudecli.LoginEnv` then narrows further for an account).

(3) **A profile's own env still sets them.** `Spec.Env`/`Launch.Env` (a legacy profile from before providers, V0.50 (7)) is appended after the scrub as before, so a profile that carries its own `ANTHROPIC_*` keeps working. Only the ambient environment loses them.

(4) **Found live.** A test run of `TestProviderLaunch` reported `base=https://openrouter.ai/api token=set-40 model=claude-opus-5-5` for a Claude account that should have passed no endpoint: the shell that started the test had an `ANTHROPIC_BASE_URL` and a token. The test's assertion was right and the product was wrong, so the fix is in the launch path and the test is unchanged. `TestAgentProcessDoesNotInheritAmbientCredentials` now sets those variables and pins the behaviour: it fails without the fix with exactly the inherited endpoint in the summary.
