# V0.fresh-ubuntu-run: what the first install on a fresh Ubuntu 24.04 found

→ #199, V0.linux-without-nix, V0.agents-unit, V0.versioned-releases. *Amends V0.linux-without-nix (4): the scope layout needs systemd 257 as well as polkit 0.106.*

The run: a fresh Ubuntu 24.04 (systemd 255, polkit 124) with nothing but `git`, `curl`, `gh` (no login) and Claude Code from its own installer, then README's steps as the owner user: `git clone`, `scripts/install-linux.sh --print`, `scripts/install-linux.sh`.

(1) **The scope layout needs systemd 257.** The script chose the scope layout from polkit 124 alone. fyrd's probe then failed (`Failed to start transient scope unit: Interactive authentication required`), and since the scope layout's unit is not delegated, fyrd ran with no cgroups at all. The cause: before systemd 257, `StartTransientUnit` asks polkit with no `unit` and no `verb` detail (`bus_verify_manage_units_async` in v255 and v256; v257 passes the unit and `start`), so the rule, which grants only units named `fyr-agent-….scope`, never matches. A rule that grants a transient unit without a name would let the user start any unit, as root too, so the fix is the layout: the script reads `systemctl --version` and takes the scope layout only with polkit 0.106 or later and systemd 257 or later (Debian 13, Ubuntu 25.04). Debian 12 (252) and Ubuntu 24.04 (255) get the V0.80 delegated unit, which worked on the run: `cgroups: on, layout unit`, the agents' budget and the PSI trigger. *Test:* `scripts` TestInstallLinuxOldSystemdUnitLayout (the other `--print` tests now fake `systemctl --version` 257).

(2) **A new install before the first version.** README's plain `scripts/install-linux.sh` failed with `no stable release (vX.Y.Z) in https://github.com/meros/fyr yet`: a new install follows `stable` (V0.versioned-releases) and no version is published yet. Now a new install that named no channel and no version, when no stable version is published, installs main's newest build and writes `updateChannel: main`, and says so (`so this new install follows main: run this again with --channel stable once a version is published`). An explicit `--channel stable`, or a config already on `stable`, still fails as before. `--print` names the fallback. *Test:* `scripts` TestInstallLinuxChannel (the new-install, `--channel stable` and config-on-stable cases).

(3) **The `fyr` command is on PATH.** The docs say `fyr auth owner`, `fyr device add`, `fyr pair` and `fyr --version`, but the install left `fyr` only at `~/.local/share/fyr/launcher/fyr`: `fyr: command not found`. The script now links `~/.local/bin/fyr` to the launcher (Debian's and Ubuntu's `~/.profile` put `~/.local/bin` on PATH, as Claude Code's installer relies on too), only when nothing else is there or the link is already its own, and says so when that folder is not on the PATH yet. `--uninstall` removes the link when it is its own. *Test:* `scripts` TestInstallLinuxPrintWritesNothing.

(4) **A host without a gh login logs its rate failure once.** The install needs no `gh` login (V0.release-without-gh), but fyrd's GitHub meter read `gh api rate_limit` every 10 minutes and logged `github rate: gh api rate_limit: exit status 4: To get started with GitHub CLI, please run: gh auth login` (two lines) each time, from the first minute on. Now a failed read is logged once, again only when the failure changes, and `github rate: read again` when a read works. *Test:* `internal/github` TestMeterLogsARateFailureOnce.

(5) **What passed on the run** (with (1) to (3) in the script): the release downloaded with `git ls-remote` and `curl` and its sums checked, with no `gh` login; `fyr.service` runs as the user (`User=` the user, launcher and fyrd its processes); `cgroups: on, layout unit` with the agents' budget and the PSI trigger on the agents' `memory.pressure`; `fyr --version` names the build; the front answers on 127.0.0.1:7777; `tailnet: off (tailscaled not running)` and `fyr auth owner` says no owner login is set and none is needed; `/api/h/<host>/updates` shows the channel, the repo and the built-in key; the agents' PATH has `~/.local/bin` from the login shell, so Claude Code from its own installer is found and Settings → Providers → Claude asks to Log in; a host put back on a build four commits behind installed main's newest by itself (`update: installing release …`, `Fyr now runs release …`) with the launcher kept; `--uninstall` removed the unit and the root files, and a second run installed and started it again.

Not proven here: the scope layout on a systemd 257 (Debian 13), the stable channel (no version is published yet), and an agent turn in its cgroup (it needs a Claude login, #30).
