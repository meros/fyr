# V0.port-race: a test install's fixed port is reserved below the kernel's ephemeral range, so no listen on :0 is handed it while the install restarts

→ V0.174 (slice 5b), V0.fix-flakes (4), the authtest harness's mesh, live fixture and LAN installs.

**The failure.** `TestBothDirectionsBlockedShowsTheReasonAndAFlapGivesOneLink` failed on an idle meros-server: "b's front never showed a's link as wanted". b's log after its restart: `peer: listen 127.0.0.1:38833: … bind: address already in use; peers are off`, then `listening on http://127.0.0.1:38833`. The restarted fyrd's own HTTP listener had taken its peer port.

**The cause.** The harness started an install with `peerListen: 127.0.0.1:0` and then pinned the port the kernel gave it (`Mesh`, `PinPeerPort`), so that a restart keeps the address in everyone's roster, as a real install's fixed peer port does. Between the stop and the next start the port is free, and it lies in the kernel's ephemeral range: any listen on :0 may be handed it. The restarted fyrd listens on :0 for HTTP before it opens its peer port, so it can take its own; so can any other test's listener. Measured here: after a port from :0 is closed, the next listen on :0 gets that very port 16 times in 100 000. The same held for the mesh's loopback host port (`HostListen`), found free beforehand and closed (`freePort`), and for the live fixture's Mac (`PinPeerPort`) and the LAN test's b.

**The fix (test harness only, no product change).** A port an install keeps across restarts is reserved (`internal/authtest/ports.go`): taken below the start of the ephemeral range (`/proc/sys/net/ipv4/ip_local_port_range`, 32768 when it cannot be read; the 10 000 ports below it), where neither a listen on :0 nor an outgoing connection is ever placed, and held by an `flock` on `/tmp/fyr-test-ports-<uid>/<port>` until the install's last stop, so no other reservation in this or another test binary of the user takes it. A candidate already listened on by something else is skipped. The mesh reserves each peer port (and host port) before the first start and passes it in the config; the live fixture's installs get one from the start (so `PinPeerPort` goes); the LAN test that pins b gives it a reserved `peerListen` (`ReservedListen`). Ports that are not kept across a restart stay on :0, read back from fyrd's log or roster.

Passing the listening socket to fyrd was not chosen: it needs a product change, and a socket the harness holds while the install is down accepts connections into its backlog instead of refusing them, which is not what a restarted install does (and the host port is closed and opened again by fyrd itself in enforce).

**Numbers.** The authtest package (50 tests, every one that restarts an install among them), `-count=20` at `nice -n 19` on the owner's laptop: passed, 1 000 test runs in 237 s. The old failure is too rare to show in a bounded run on an owner's laptop (one restart in some thousands); the mechanism is the measured 16 in 100 000 above, and after the fix no listen on :0 can reach a reserved port.
