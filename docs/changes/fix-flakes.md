# V0.fix-flakes: the tests that failed on a busy host are fixed at their cause, one gate runs at a time on a host, and two messages sent at once reach the agent in order

→ V0.33 (message delivery), V0.45 and V0.96 (4) (handover), V0.60 and V0.101 (actions, Stopped on a failure), V0.133 (the fake's background tasks), V0.165 (full screen), V0.174 (slice 5b), the local gate of #405.

The owner (19 Nov): "Fix the flakes when you encounter them (new Claude rule in repo)". The local gate (`scripts/ci-local.sh`) failed on tests that pass alone, while several gates ran on the host at once. Each was run alone and under load (`go test -count=N` beside 8 busy loops, or 6 test binaries at once); the numbers are failures before → after, same load.

(1) **A product bug: two messages sent at once could reach the agent out of order.** `send` decided "first message of the turn" under the manager's lock, released it, recorded the message and then wrote it. A second message sent in that gap was written first, so the agent answered the later message before the earlier one. `TestUnreadMessageLostWithProcess` caught it: "later" was answered before "hang" started. Each session now has a send lock held from that decision to the write (`internal/agent/outbox.go`). 4 of 1800 → 0 of 1800 (6 test binaries at once, 8 busy loops).

(2) **Handover: the test read the log before the target's first message was in it.** The handover ends (`Handover` nil) before the target's first message is recorded. `TestHandoverFirstMessageListsOpenChanges` and `TestHandoverBriefWhenExportFails` read the events at once. They now wait for the handover messages (`handoverTexts`). 12 of 400 → 0 of 400.

(3) **`TestChangeActions`: the clock moved before the run the failure woke had ended.** A failed action wakes the agent; the failure is the owner's 5 minutes after that run (`StopAfter`). The test moved the engine's clock 30 minutes ahead while that run could still be going. A run that ended after the move was stamped on the new clock, so its 5 minutes never passed and the thread stayed Done. The test now waits until a run has read Fyr's line about the rollback (the fake echoes it, alone or fed into another message) and has ended, then moves the clock. The "one snapshot" workaround goes. 6 of 200 → 0 of 200.

(4) **`TestBothDirectionsBlockedShowsTheReasonAndAFlapGivesOneLink`: a link up is not yet the front following the host.** After the ACL flap the test waited for the link to be up on both sides and called b through a's front. a's front reconnects its stream to b on its own retry, and until then it answers 503 "b is offline". The test now waits for a's front to follow b (`waitHost`), as the one-direction test above it does. 2 of 40 → 0 of 40.

(5) **`TestListSaysInputClosed`: the fake CLI counted its background task after its result.** `bgwait` wrote the turn's result and then did `bgwg.Add(1)`. The test closes stdin on the result, and the fake's exit (`bgwg.Wait()`) could run before the Add, so it exited before its background task. The fake now counts the task before the result. #233 had lengthened the task; that was not the cause. 7 of 600 → 0 of 600.

(6) **`TestShootRealChrome`: reuse is proved by the process, not a wall-time budget.** The test asserted that the second shot took under 5 s, as a proof that the browser was reused; a busy host took 5.77 s. It now checks that the second shot ran in the same Chrome process, still running (`c.cmd` unchanged, not dead). That proves reuse on any host. The check that Close ends Chrome's process group waited a fixed 300 ms; it now polls for up to 10 s. Not reproduced here (0 of 48 before, under load); the cause is the budget the failure names.

(7) **V0.165 layout: the press on the image's Full screen came before the layout settled.** Without the Fullscreen API, the test left the HTML preview by Back and pressed the image's Full screen at once. Every other leave in that section settles first: the card returns to its place and the thread moves for a few frames. The failure showed no viewer and the URL unchanged, a press that missed. It now settles first, and the section's press takes its point only when that point hits the button itself (`elementFromPoint` inside it), not a layer still closing above it, besides holding still for two frames. Not reproduced before (the layout test was queued by the host's admission then); after, 0 of 15 runs of the V0.165 full screen sections beside 8 busy loops.

(8) **One gate at a time.** `scripts/ci-local.sh` takes a lock (`flock` on `fyr-ci-local.lock` in the user's runtime dir, `/run/user/<uid>` when `XDG_RUNTIME_DIR` is unset, so a shell and the service share it) before `make test`. A second gate says "ci-local: another gate runs; waiting", and its status stays `pending` ("waiting for another gate on <host>") until it runs. The gate's commands run without the lock's descriptor, so a process the gate leaves behind (a detached Chrome) does not hold it. The "layout test: timed out" seen while make waited after a Go failure was its 420 s hang guard on a host loaded by several gates; the lock removes that load.

(9) **`TestV176BLiveThreadKeepsLeftoversUntilIdleLimitUnlessKeptOrTimed` now asserts what the tracker itself signalled** ("a kept, timed or CLI process was ended"). It failed once in 600 runs while other packages' tests ran beside it, and never in 350 runs under busy loops alone. No path in the tracker ends a kept, timed or CLI process: it signals only the pids of the leftovers it ends (`endPIDs`), each checked against the start time it saw, and nothing in it signals a process group. The processes are real, though, and live in this host's cgroups and process table, where the host's fyrd (its guard, its own leftover tracker) and other test binaries act too; a liveness check proves the test's claim only if nothing else touches them. The claim is "the tracker does not end them", so the tracker now sends its signals through `Leftovers.Signal` (default `syscall.Kill`), and the test records them and fails if one went to a kept, timed or CLI process; the leftover it ends is still ended for real. The external killer was not identified in the time-box (pid reuse is ruled out: pids here advance about 0.4M a day of 4.2M). 0 of 20 runs of the leftover tests after; the old failure rate was too low to measure in the time left.

(9b) **Layout mock clocks (V0.176, V0.195), found by this branch's own gate.** V0.176's worktree "Fyr removes it in N h" took its removal time from the real `Date.now()` while the rail mock runs on 14:32 today, so before 09:32 it read "in 1 min" and the check failed every run (2 of 2 alone at 06:20 → 0). V0.195's background command started exactly 35 min before the mock's clock; the front's clock is the host's less the reply's delay, so under load it read "34 min". It now starts 35.5 min before, mid-minute (failed 1 of 1 in the loaded gate, passed alone → passes).

(9c) **Found, not fixed here: `peerlink` `TestSimultaneousDialsLeaveOneLink`** ("unexpected EOF", 1 of 1000 iterations alone). A product race: when a late dial from the smaller id replaces a link both sides already use (`register`), the loser's `drainAndClose` waits only for the requests this side has open on it, not for those the peer has open or is starting before it sees the new link, so such a request ends in EOF. It needs its own change (count the requests served, and close only once the peer has moved to the new link).

(10) **The rule.** CLAUDE.md: a flaky test you meet is fixed at its root in its own change, not retried until green; before you call a failure a flake, run the test alone and under load.

The "sql: database is closed" lines around the engine failures come from earlier tests' agents that outlive their store. They are noise in the log and were not the cause of any failure above.
