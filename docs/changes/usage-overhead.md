# V0.usage-overhead: Fyr's overhead inside agent turns is measured and shown on the Usage page

→ V0.usage-ledger, V0.usage-page, decision 0041 (phase 4, parts O2 to O4), SPEC 3.18, API-v0. Fyr's own calls were counted (V0.usage-jobs), but not what Fyr adds inside an agent's turns: its prompt and tools in every request, its tool results and notices that stay in the context, and the turns the Stop hook forces to keep the live view.

(1) **Fixed context (O2).** A process's static key names what Fyr adds to each of its requests: its appended prompt, its MCP tools (their hash) and the CLI tools it takes away (`agent.staticKey`). A turn keeps its main-agent requests and how many found the cache cold (a cache read under a fifth of the context) by key and model (`usage_static`). The first time a key runs on a model, a calibration measures it (`Manager.calibrate`): two print runs of the same CLI with a one-word prompt, no settings files and no other MCP server (`claudecli.ProbeArgs`, `cli.Prober`), one with Fyr's prompt, MCP server (on a token that names no thread, gone when the run ends) and tool lists, one without; the difference of their one request's context is the key's tokens (`usage_calibration`). The schema size would be the wrong measure: the CLI may defer MCP tools. Both runs are ledger rows with source `calibration`, which is overhead too. The overhead is computed when read: calibrated tokens × warm requests as cache reads, × cold requests as cache writes; requests of a key not measured yet are counted as uncalibrated, and the next read after the calibration includes them.

(2) **Tool results and notices (O3), an estimate.** Per session, between two main-agent requests the context grows by the blocks added since; the growth is split by the bytes of Fyr's blocks among them (`mcp__fyr__*` tool calls and their results, Fyr's notices in a message or a hook's context, a notice or handover turn's text, the Stop hook's reason). Exact when only Fyr's blocks were added. Fyr's tokens stay resident and each later request reads them again, until a compaction (the context shrinks below 70 %) empties them. A turn keeps the tokens that entered (cache write) and the ones read again (cache read) in `usage_overhead`, with the method named.

(3) **Forced view turns (O4).** The requests after the Stop hook's synthetic message: their input side exactly, their output as counted at the request's start (a lower bound: the stream says no more).

(4) **Reads.** `GET /api/usage/overhead` sums a range's overhead with the filters of `/api/usage` (not by model or part, which are not a turn's), by part and kind, and the uncalibrated requests. Settings → Usage shows "Fyr's overhead in agent turns" on both fronts: the three parts with their kinds and their share of the range, inside the turns' tokens and not on top of them.

(5) **What it leaves out.** Subagents' requests (they get Fyr's tools, not its prompt) are not in the static part. A process adopted after a restart of fyrd has no static key and starts its resident count from zero. agy has no probe: its turns have no static part.

(6) **Against the decision's sketch.** The decision named one table `usage_overhead(usage_id, part, tokens, method)`; the fixed context is kept as facts (`usage_static`) and computed when read, so a calibration measured later applies to the turns before it.
