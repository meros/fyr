# V0.project-archive: a finished project can be archived; it and its threads leave the inbox and the pickers until a new message brings a thread back

→ decision 0017 (a project keeps archive), decision 0034, V0.207. Closes the archive that the cut-down of 0017 left unbuilt.

A finished project kept its threads in the inbox sections, its chip in the project filter and its row in every project picker. The only way out was to settle or archive each thread, or to delete the project and lose its filing.

(1) **Host.** `project.archive {id}` sets the project's `archivedAt` and, in the same write, `thread.shelve` on each of its threads that is not archived (`shelvedAt`). A thread is not otherwise touched: its state, its changes, its worktree and its place in the list stay. `project.unarchive {id}` clears `archivedAt` and every `shelvedAt` of the project's threads. Both answer `{id, kept: true}` for a project already there. The code is `internal/core/projectarchive.go`; the engine adds the thread inputs to the project's write (`ArchiveFollows`).

(2) **Refused while work is live.** A thread that has a live or starting run, a message on its way to the agent, or an open question cannot be shelved, so the archive is refused (`409`) with the reason, naming the thread: “Deploy” is working: stop its run or wait for it first; “Deploy” has an open question: answer it first. The fronts work out the same reason from the threads they hold and show it in the Archive row's text and on the disabled button (the phone has no hover, so a tooltip alone would hide it there).

(3) **A new message brings back the thread, not the project.** After every reduce, a shelved thread that has a run, a message for its agent or an open question loses `shelvedAt`: the owner's message, another agent's, a wake-up and the agent's question all bring that thread back to the inbox. The project stays archived: one more question in an old thread is not the project starting again, and Unarchive is one press. The project is not offered in the filter or the pickers while a returned thread shows in the inbox.

(4) **The fronts.** An archived project leaves the store's project list on both fronts, so the project filter and every picker (New thread, Hand over, Project…) lose it; a thread whose own project record is archived and that is shelved leaves the inbox sections, their counts and search. The threads stay in the store, so one still opens. **Settings → Projects** (the desktop's Settings and the phone's Settings screen alike) lists the archived projects under "Archived projects"; their page, the same project page as before, has Unarchive and lists the project's threads to open. Archive on the project page sends the command and offers Undo in the toast, like a settle; Undo unarchives the records it archived. Changes (the board) and worktrees are untouched.

(5) **Linked projects (decision 0034).** Archive is the owner's word about the project, not about one host's folder, so it goes to every member like the shared values: the client sends `project.archive` to each member's host that is not archived yet (Unarchive likewise). A linked project counts as archived when every member is. A member on an offline host, or one that refuses, stays as it was and the error names its host; pressing Archive again archives the rest. There is no catch-up through the front as for the shared values: a member that missed it shows the project as active until the owner presses again.

Tests: `internal/core/projectarchive_test.go` (archive and unarchive with their thread inputs, the refusal per kind of live work, the return on a message, a run and a question), `internal/engine/projects_test.go` (TestProjectArchive: the refusal through the engine, one write, a message brings back one thread, unarchive the rest), `web/test/archived.test.ts` (the store and inbox filters, the archived list, the refusal text, a linked project), `web/test/layout.e2e.mjs` (V0.project-archive desktop and phone: Archive and its Undo, the refusal, the inbox without the project, the archived list and a thread opened from it; two phone screens).
