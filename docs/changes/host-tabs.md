# V0.host-tabs: multi-host screens share one tabbed host switcher instead of stacking every host vertically

→ V0.126, V0.127, V0.132, V0.139, V0.166, V0.167, V0.automation-folds, decision 0034. *Amends V0.127 (Settings → Providers and Automation show one host at a time behind a shared tab bar instead of stacking every host's section vertically), V0.132 & V0.139 (HostField picks a host with the same tabbed strip and each host's mark instead of a native select), V0.166 (the phone's Host load sheet tabs by host and shows that host's quotas), and decision 0034 (a linked project switches between host members with the same tab bar).*

With three or more hosts, stacking every host's full Providers, Automation or Host load sections vertically made those screens very long, while linked projects, the Hosts sub-page and HostField pickers each used a different way to switch hosts.

(1) **One shared component (`HostTabs`, `web/src/host-tabs-ui.tsx`).** Shared by desktop and phone; renders nothing with one host. Each tab shows the host's mark (`HostMark`, with its offline corner ring when offline), its mono name, an optional live reading (e.g. load share on the load sheet) and an optional amber attention count badge. Horizontal scroll keeps many hosts on one line; ArrowLeft/ArrowRight/Home/End move between tabs; `SlideMark` slides the indicator. Phone touch targets are 44 px via CSS.

(2) **Settings → Providers, Automation and Setup.** `HostParts` renders `HostTabs` in the owner's host order above a single active host panel (`.hpart`). The chosen host is remembered across Settings pages during the session so switching from Providers to Automation or Setup stays on the same host, and returning from a provider sub-page (crumb, Esc or Back) stays on that host's tab. Providers badges each tab with its unready providers and blocked system jobs; Automation badges leftovers, undeclared work, held-back releases and low GitHub API limits. Clicking a host's leftover count in the rail opens `automation/<host>/leftovers` directly on that host's tab. Setup now inspects and fixes every host rather than only the first online one. On Automation, Services and Kill and rerun also fold with a count summary like the other reference groups.

(3) **Settings → Hosts (host sub-page) and linked projects.** A host's detail page (`Settings → Hosts → <host>`) renders `HostTabs` at the top to switch directly between hosts (replacing history on the phone so Back still returns to Hosts). A linked project (`ProjectEditor`) renders `HostTabs` directly under its header in the owner's host order, removing the stacked "Also here" rows and folding the link/unlink controls into a compact Hosts group.

(4) **Phone Host load sheet and HostField pickers.** `LoadSheetBody` tabs by host when several exist, showing each host's live load percentage in its tab and only the selected host's meters, load card, leftovers and provider quotas below. `HostField` (New thread, New project, Adopt from T3, Hand over) uses the compact pill variant of `HostTabs`, showing each host's mark directly; New thread's quota views filter to the selected host.
