# V0.settings-ia: a host's page holds its own; Settings has two groups, one count and one name per thing

→ V0.119, V0.125, V0.126, V0.127, V0.157, V0.159, V0.164, V0.176, V0.207, V0.automation-folds, V0.host-tabs, V0.host-updates, V0.notification-polish, V0.setup-wizard, V0.usage-page; decision 0031 2.6.

Why: a host's settings lived on four pages, and the page named after the host had almost none of them. Automation held fifteen groups of which two were automation. The counts at the door (the More row), in the nav and on the host tabs disagreed, and the desktop had no count at all, so a login that expired was first seen as a failed thread. Several things had two names, and one sentence about ★ was not true.

(1) **The nav has two captioned groups, the same on both fronts, sorted by where a setting is kept,** so each caption is true of every page under it. *Only on this device:* This device. *On your hosts:* Sign-in (was Devices; its page id stays `devices`), Providers, Projects, Automation, Hosts, Usage, Setup. Sign-in is the devices signed in to the host this device is connected to, so it is a host's page and its lede names that host. On the desktop a nav line is one line (an ellipsis, the whole line as the tooltip). Setup's line counts every host and says which it could not ask: "Ready", "Ready on 2 of 4 hosts · 2 not read".

(2) **Automation is only what Fyr does without a press:** Auto-update, Auto-merge, and Per project, a row that names the two per-project switches and opens Projects. **The Auto-update switch exists once, here;** under it one line of state opens the host's Updates (red while that host holds a release back). **Auto-merge says its scope:** each host keeps its own list, and a thread's merge ask follows the list of the host the thread runs on; a host tab with no repos says why. *Amends V0.automation-folds (1)–(3): the groups it folded are on the host's page.*

(3) **A host's page,** top to bottom, the same on both fronts. *Amends V0.125 and V0.host-updates.*
 - **Jump links** to its sections, each with a word only when it is not fine ("Updates · held back"). The word has the count's colour only when this host's tab counts it (its update, while the host is online); memory, diagnostics and what Providers and Setup count for this host ("1 on Providers") are muted. The desktop wraps the links to a second line when they do not fit; the phone keeps one line that scrolls sideways under a fade (its links are 44 px high for touch).
 - **What needs the owner:** a changed id (both ids and Trust…); one note when the host is offline or too old to be read (the note says how to update it: on that machine); a row when a required setup check is not ready.
 - **Six sections under one heading level:** *Updates* (the one row that asks for a press, with its reason and its button: Update now, Try again, Back to release; what runs, the newest release, the last update; a line that says whether Auto-update is on and opens Automation; Update history, folded, open while a release is held back). *Load* (Memory now; Running now: Leftover processes, Heavy work Fyr did not expect, Unused worktrees; Rules: What counts as heavy, Kill and rerun, Service commands, Learned commands, Measured jobs: everything that tunes how much the host's agents may use is under Rules, and the budget row says Fyr sets it by itself). *Providers and setup* (two rows that open this host's providers and its setup checks). *Diagnostics* (Memory guard, Load invariants, Thread invariants, GitHub API, Release source and key; its groups show whole). *Look* (Mark, folded once it is set; Show on this device). *About* (the id with Copy, how Fyr trusts and reaches it).
 - **Remove this host…** last, for a paired host.
 - **Setup checks exist once, on the Setup page** (a tab per host): each read runs the checks live on the host, and Setup is where the first run lands. A host's page shows their state as a row that opens Setup on that host's tab.
 - **The folding rule,** stated above `HostPage` (`settings-hosts.tsx`) and computed by `foldNow` (`settings-fold.ts`): what the owner acts in is open; what only reports, or is set once, is folded and its header says the state; a folded one that reports something wrong now shows its line in the error colour and is open, as is the section a link landed on; what the owner opened or closed is remembered on the device, and one press always closes a fold. A default that changes after the page opened (a report that arrives late) applies.

(4) **Links.** A section of a host's page is `hosts/<host>/<section>` (`updates`, `load`, `more`, `diagnostics`, `look`, `about`, and `leftovers` for that group). `setup/<host>` and `automation/<host>` open that host's tab. Older links land: `automation/<host>/leftovers`, `automation/leftovers` (no host: the first host; Esc, the crumb and Back treat it as that host's page, and the phone's address names the host), `hosts/<host>/setup` (Setup on that host's tab). The rail's leftovers count uses the new form, and the phone's load sheet has the same link as a button (Settings then takes the sheet's place in the history). *Amends V0.176, V0.host-tabs.*

(5) **One count, one rule** (`settingsCounts`): a thing counts only if the owner can act on it now, and every counted thing has an amber chip on the row where it is fixed; nothing has that chip without being counted. Counted: a provider without its login or key, one of Fyr's own calls that cannot run, a host whose id changed, a release a host holds back or an update that failed, a device waiting to be allowed, a required setup step. Not counted: anything a host holds while it is offline (its rows say the same in grey), a host too old to be read, what Fyr handles by itself (leftover processes, undeclared work, a low GitHub limit), and everything while this device has no connection (no press reaches anything: the gear, the More row and the nav show no count, and every chip is grey). A held-back release is read one way (`updateTrouble`: the host's own summary, else its settings read) by the count, the Hosts list's row, Automation and the host's page. The desktop's gear (which now shows the count, as Changes does), the phone's More row, the nav's badges and the host tabs show this count over the same hosts, the ones this device hides too; the gear's tooltip and the More row's line name the pages that hold it ("Sign-in 1 · Providers 1"). The door and the pages count through one function (`countsFrom`, `settings-count.ts`), so the number at the door is the nav's before Settings was ever opened. **Its cost:** outside Settings it reads each online host's providers and Fyr's own calls, the devices that wait, and, for a host whose row carries no update summary, what it holds of its updates; never a host's setup checks, so a required setup step counts once Settings has read it. It is read again when the hosts' rows or the state's provider status change, when the connection comes back, when Settings closes, when the window gets the focus, and every five minutes; the Setup page keeps the kept report current, so a step fixed there leaves the gear at once. Sign-in's list is read when Settings opens and every 5 s on its own page only. *Amends V0.125 (the More row counted providers and changed ids only) and V0.host-tabs (the Automation tab's badge is gone with its groups).*

(6) **A project's page** is ordered: header (with "On host" and the host, on a front with several); Identity; New threads (Folder, defaults); Without asking (Agent says done, Tool approvals); Priority; Quiet hours; Show on this device; Other hosts (linking, folded, in the same place whether linked or not; absent with one host); Archive; Delete. **Show on this device** is the same per-device setting as the row in This device's list (V0.207), which is folded with "Everything shows" and open while something is hidden; a host's page has the same switch. All three work with no connection. *Amends V0.139: an unlinked project's linking controls no longer sit above Identity.*

(7) **Hosts** is the list (a counted row has its amber chip: "Needs you", "Update held back", "Update failed"; a grey chip is state and says why it is not counted: an offline host's "Update held back · offline", "Update needed"), then one group **Add a host** (Invite from here, with Create invite; Join with an invite; Address of the other host), then **Found, not paired** and **Pairing**, both folded with their count. On the phone a row shows only the amber chip (the line says the grey one's words; width), and Reorder mode shows a host's mark and name only. *Amends V0.159: three groups in this order, where there were four.*

(8) **Names: one word for each thing** in every label, help text and error on these pages, the ones a host sends for its Setup steps too ("This host", "Other hosts", "Paired with 1 other host"). *host* (not install, machine or front; the pipe's route in a host's line is "this host", *amends the word of decision 0031 2.6*); *this device* (not this browser); *needs you* (the host tabs' badges too); **Allow** (a waiting device; "Allow by code"); **Sign out…** on every device's row (Revoke is gone); **Remove…**; **Check now** (Setup's and a provider's models' re-read); Forget (a measured job's learned cost). "System agents" is "Fyr's own calls" (Usage's words), with its per-job rows folded under Per job. Auto-update and Auto-merge have one name each in the group, the switch's label, the nav's line and the error text. A provider's "Usage" group is "Quota". "Set up automatically" on a host and a project is "Fill in automatically". "fyrd" and "cgroup" do not show. Providers says, under its list, where a new thread's provider and model come from (the project's defaults, else the last pick on this device, else the first ready provider and its ★); the line under a provider's models says what ★ does.

(9) **Three levels of a press** (`ConfirmButton`, `settings-asks.ts`). One that can be taken back acts at once (Keep, Remove a worktree or an added pattern, Unlink, Archive). A small one that cannot be taken back and touches this host only asks in place: the first press sends nothing and its label ends in "…", then the act in red and Cancel (focus on Cancel; Esc cancels and the focus goes back to the button): End a leftover process, Remove a learned command or a built-in service pattern, Trust a changed id, Sign out. What loses stored data for ever or reaches another machine asks in the confirmation dialog, which names the object: Delete project, Remove provider, Remove a host. Require sign-in asks in the dialog when turning it on would refuse requests that still get in. On the phone the two buttons of the inline question take the place of the row's other buttons, and a row that ends in several buttons has them on a line of their own (width).

(10) **Forms.** New project in Settings is the sub-page `projects/new` with Cancel; Add provider is in the Providers title line (first on the page on the phone) and lands on the new provider's page. A form left by Esc or Back keeps what was typed while Settings stays open, except a pasted API key, which is never kept; Cancel and adding empty it. `providers/new` with several hosts and none named opens on the first host, and New project opened by a link starts on the first host once the host list has arrived.

(11) **Fixes.** The desktop dialog follows the window (`min(1100px, 92vw)` × `86vh`; it was 820 × 640). The inline question's class no longer restyles the confirmation dialog. The "this device" pill is a small pill beside the name. On the phone a row with two selects no longer has a 200 px hole. A leftover whose thread this device does not know says "of a thread that is gone" and has no Open. The memory guard's chart keeps its text size on every width. A host's Load keeps its place while the load is read, and with several hosts a host without a reading no longer shows another host's. Usage's groups keep the pane's gap. Sign-in's order is what waits first, the group "How this device gets in" last. The notification choices (Finished threads, Quota resets) show, disabled, while notifications are off (*amends V0.notification-polish, which hid them*). "API key: Set · set · ••••4f2a" is "Set · ••••4f2a". A provider's open login panel says "Sign in below", not the host's "Press Log in". A nav line whose read failed says "Could not read". With no connection, This device stays usable and shows no banner; a host's line under the tabs, its pill and its row on the Hosts list read "As last read", not "Online". The mock's two sources of a held-back release agree (`?held=1` holds one back on desk).

Not done, on purpose: a global default provider or model for new threads and reordering providers (they need a host-side setting); setting the heavy-job budget (the host moves it by itself; no command sets it); a token figure in Usage's nav line (a read of every host on each open); Setup saying Ready beside a provider that needs a login (the report is the host's); one row per host for Auto-update on Automation (the page keeps its host tabs, which Auto-merge needs; the nav's line says "on 3 of 4 hosts").
