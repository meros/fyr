# V0.versioned-store: the store has a schema version, its migrations run once at open, and the repairs of shapes stored before V0.100 are gone

→ SPEC 3 (Records: stored data, and the third exception to 5.1), V0.structure-cost (2), V0.spec-from-code (1). Issue #456.

The problem: every load ran every repair of every shape an older build had stored, outside the reducer, in the decoder of each thread and view and in three engine passes (projects' sources, auto projects, the load passes of `core.Migrate`). Nothing recorded that a store was already repaired, so the passes ran on every start, and the code for shapes no store still held could never be removed.

(1) **A schema version.** The key-value table holds `store.schema`: how many migrations the store has run. `store.Open` reads it and runs the migrations after it, in order (`internal/store/migrate.go`). Each runs in one transaction with the write of the version it reaches, so a migration that fails or a crash leaves the old version and nothing it wrote, and the next open runs it again. A second process opening the same file reads the version again inside the transaction and does not run a step twice. A store at a version newer than the build's (a rollback after a deploy) opens as it is, with a log line: every step so far only repairs records in the shape the older build reads.

(2) **Migration 1** is the load passes the engine ran on every load until now: V0.98 (7) and V0.105 (2) (what landed or ended is done, on threads and host records), V0.changes-code-only (4) (a change that is not code ends), V0.structure-cost (2) (a Rule on the retired `noDecisions` Condition). They run once per store. The engine's `Load` keeps only what is not a migration: records that ended over 30 days ago expire.

(3) **The cut-off: a build of 16 Nov 2026 (V0.100).** The owner's hosts update several times a day, so each has run a build from after it. Gone: the decoder's repairs of a thread stored before #31 (`offerRuns`, a change's `actions`), #32 (the PR on the thread, `dismissedPRs`, `settleWhenMerged`, `pr` evidence), #33 (`settledAt`, `settleWhenDone`, `settleWhen`, `liveView`), #35 (observed git changes in the thread), #46 (`settle.when`, `deployWatch`, the built-in actions' Rule) and #48 (the deploy watch's change-ended clause), and V0.70 (`landedAt`); the view's `snoozeUntil` (#46); the projects' `sources` (V0.55) and `auto` (V0.28) with `Project.Auto`. The V0.95 fixture sweep was already retired by V0.structure-cost (2).

(4) **An older store is refused, not misread.** A store with no version is checked once, before migration 1, for the keys only those builds wrote (on a thread, its changes, its settle, a view, a project). The pass of #35 stored what it moved. Three repairs were in memory only and leave no key to check: a deploy watch without its change-ended clause (#48; its time limit still ends it), a landed change without `landedAt` (V0.70; migration 1 files it as done) and `pr` evidence without a PR (#32). A thread untouched since before the cut-off that holds one loads without that repair. If a key is there, `Open` fails, naming the oldest supported build and up to ten records with their keys, and writes nothing. A deploy's self-test opens a snapshot of the store with the new build, so such a host keeps its running build and reports the error. The way forward is to keep running a build from before this change on that store, or to move `fyr.db` aside and start with an empty one. The earlier builds repaired those shapes in memory only, and stored a thread again only when a reduce changed it, so a thread untouched since then can still hold one; on the one host checked, no thread, view or project did.

(5) **A new migration** goes at the end of the list and is never changed or removed while a store may be below it.

Tests: `internal/store/migrate_test.go` (TestOpenMigratesOldestStore: a store of the oldest supported shape, built in the test, migrates to the current one and a second open changes no byte; TestOpenNewStoreIsCurrent; TestOpenRefusesOlderStore; TestFailedMigrationKeepsVersion; TestOpenNewerStore), `internal/engine/codeonly_test.go` (TestLoadEndsChangesThatAreNotCode) and `internal/engine/done_test.go` (TestLoadMarksLandedDone), which now load a store with no version. The tests of the retired shapes are removed with them.
