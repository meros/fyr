# V0.tool-approval-judge: per-project approval judge for agent tool approvals

→ extends V0.115 (system agents), V0.108 (one-shot print runs), decision 0034 (linked projects), and V0.21/V0.41 (calm timeline).

Agents that run inside a sandbox (such as `agy` calling `run_command` with `BypassSandbox: true` for network commands like `gh pr create` or `git push`) frequently trigger blocking `can_use_tool` permission prompts for routine work. Always-allow allowlists are brittle on compound shell commands with wrappers (`cd … && nix develop -c …`), while blindly skipping all permissions is unsafe.

1. **Per-project switch (`Project.toolApproval`):** each project has a two-state setting — `Ask me` (default, stored as `""`) or `Auto-judge` (`"auto"`). Unfiled threads always ask. On a linked project (decision 0034), `toolApproval` is a shared field synced across hosts via `front.projectShared` / `project.shared`.
2. **Allow or ask only (fail closed):** when `toolApproval` is `"auto"`, Fyr runs a one-shot judge call (`cli.Printer`) before opening an approval card. Deterministic policy gates (`core.Gate`, e.g. `gh pr merge`, `sudo`) always run first and deny before the judge. The judge may only return JSON `{"decision":"allow"|"ask","reason":"..."}`. Any timeout, provider error, or unparseable reply fails closed to `ask` with a short note.
3. **Prompt-injection boundary:** the judge receives only trusted project/thread metadata, recent owner-authored `user` messages (plus the parent thread's initial brief for child threads), and the proposed tool call fenced inside `<tool_call>…</tool_call>` as untrusted data — never assistant text or tool outputs.
4. **System agent configuration (`JobApproval = "approval"`):** **Settings → Providers → System agents** adds a **Tool approvals** row. Its default is `Thread's provider (auto)` — running on each thread's own provider with its fast model (`claude-haiku-*` on Claude, `gemini-4-hydrogen` then `*flash*` on Antigravity, at `low` effort when the model supports effort levels; custom endpoints fall back to their default/thread model). The owner can override it to `Same as default` (`$default`) or any host provider and model.
5. **Auditability and approval card clarity:** auto-approved calls record a quiet `decision.autoApproved` timeline event that folds with process work (V0.41) without waking the owner. Escalated approval cards (desktop and phone in sync) display `judgeNote`, omit duplicate `CommandLine` when equal to `command`, render `BypassSandbox: true` as an `Outside sandbox` badge, and clamp commands over 8 lines behind a `Show full command` toggle.
