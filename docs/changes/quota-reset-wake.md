# V0.quota-reset-wake: wake a thread when a provider's quota window resets

→ V0.44 (each window carries `ResetsAt`), V0.122 (token accounts read only from sessions), V0.wakeups-via-watch (the wake chip and cancel), V0.quota-in-thread (the quota chip on desktop and Details on phone), V0.notification-polish (per-device push prefs), #500.

A thread that stops because a provider is out of quota can now be armed to continue when the provider's quota window resets — either by the agent through `mcp__fyr__watch`, or by the owner from the thread's quota chip (desktop) or Details sheet (phone). Nothing switches providers or retries automatically (decision 0013).

1. **The watch condition.** `WhenQuota = "quota"` (`{kind: "quota", provider?, window?}`) is a new `core.When` condition, usable with `then: "notify"` or `then: "settle"`. When `provider` is omitted it defaults to the thread's profile; when `window` is omitted it picks the binding exhausted window (≥ 100 %) or, if none is exhausted, the soonest-resetting window.
2. **Resolved on the host, never invented.** `quota.Service.ResetOf` refreshes due OAuth profiles (never polling token accounts or rate-limited profiles) and refuses stale readings, balance providers, token accounts with no known reset time, and windows without a future `ResetsAt`, returning the reason.
3. **Follows a moved reset.** When a fresh provider read or `rate_limit_event` updates a window's `ResetsAt`, `quota.Service.OnUpdate` calls `Engine.SyncQuotaResets` (`quota.sync`), which updates matching armed `WhenQuota` rules (within 1 h drift, so a newly started next window never postpones an already-due wake).
4. **Owner action and UI (both fronts).** `thread.wakeOnQuota {provider?, window?, note?}` arms an owner-owned `WhenQuota` wake and clears a thread's failure so it moves out of Needs you into Working/Waiting. On desktop, clicking the header's `ThreadQuotaChip` opens the quota card with per-window `Wake when 5 h resets (18:00)` / `Cancel 5 h wake` buttons (disabled with the reason when stale or without a reset time); on phone, the thread Details sheet's `Quota` row renders the same shared `QuotaWakeActions` component at 44 px touch height.
5. **The chip and cancel.** Armed quota wakes appear in `thread.wakes` (`{rule, at, note?, provider?, window?, by?}`), rendered by `wakeChip` and `WatchWaitText` as `wakes 18:00, when the 5 h window resets` (with the date when not today). Pressing the header chip cancels it via `thread.cancelWake` (notifying the agent for agent-armed wakes; cancelling quietly for owner-armed ones).
6. **Optional push when the thread still waits.** When a quota watch fires (or an exhausted window passes its `ResetsAt` while a thread on that provider is stopped on a failure), the host emits `stream.FrameQuotaReset`. After `NotifyDelay`, if the thread is still waiting (not `working`, `settled` or `archived`) and push is allowed, the front pushes `state: "quota"` to devices that turned on **Quota resets** in Settings → This device (`push.Prefs.QuotaReset`, off by default).
