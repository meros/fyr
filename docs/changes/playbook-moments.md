# V0.playbook-moments: a stage the owner checks asks them when a change gets there, a manual deploy is a Run card, and a playbook entry can be added by hand, suggested and doubted

→ V0.project-playbook, V0.ask-tool, V0.149, 3.15. *Amends V0.project-playbook (2) (an agent's write on the owner's entry was refused; it is now kept as a suggestion) and its list of what was left out.*

Why: the playbook said where a merged change is, but the moment a change can be tested passed in silence unless an agent had armed a watch for it, and a project that is deployed by hand still needed someone to remember the command. On the page, an entry could only be corrected, not added; a long text was cut off in its one-line field on a phone; an agent that found the owner's entry out of date could only say so in its thread; and a probe that never succeeds looked the same as one that works.

(1) **The owner's check.** A stage may carry `ownerChecks`. When a merged change reaches such a stage, Fyr opens a question card on the change's thread: "PR #12 (its title) is on dev: <address>. Does it look right there?", with Looks good and Something is wrong (the owner can always answer in their own words). It is the ask of V0.ask-tool, opened by Fyr: the thread is in Your move and the owner is notified, on a settled thread too. No model runs until the owner answers; the agent then hears the answer as it hears the answer to a question of its own.

(2) **A manual deploy is a Run card.** A stage may carry `deployCmd`, the shell command that puts a merged change there by hand (`{sha}` is the merge commit). When the stage before it holds the change (the merge itself, for the first stage) and the change is not on the stage yet, Fyr puts a Run card on the thread with the command for that commit, in the project's folder: "Deploy PR #12 to prod (the project's playbook)". When the stage before it is one the owner checks, the card comes only after their Looks good; Something is wrong, or closing the question, holds it. The owner's press runs it and the agent hears the result (V0.149). Fyr never runs the command itself, so it needs no separate yes.

(3) **Once, and only when fresh.** Each moment happens once per change (`change.staged`: `ask:<stage>`, `ok:<stage>`, `run:<stage>`), opened by the host each minute as the Input `stage.moment` of the deploy observer. It opens only within 24 hours of the stage being reached and only for a stage reached after its entry was written, so turning a check on asks nothing about changes deployed long ago. Stages GitHub Deployments report get the same moments as probed ones.

(4) **Suggestions.** What an agent writes on an entry the owner wrote is stored beside it as `suggest`; the entry stands. The page shows what differs with Take it and Dismiss (`project.learn {…, take: true}` or `{…, dismiss: true}`, owner only). A taken suggestion is the owner's entry; a probe it changed waits for the owner's yes like any other. An agent still cannot remove the owner's entry.

(5) **Doubt.** When a merged change's watch ends (a day without the stage reached) while an allowed probe of the stage never saw the commit, the entry's `missed` goes up by one (`project.probed`); the next merge the probe sees clears it. From two in a row the page says the probe is in doubt and opens the group, and the agents' prompt says so, so the next agent in the project checks it. The count is this host's and moves no stamp. A stage that is simply released more than a day after the merge is counted too; the mark asks for a look, it changes nothing by itself.

(6) **The page, the same on the desktop and the phone.** A text is in a field as tall as it is, so a long sentence or command is read whole on a phone; Save stands beside it while it differs. A stage has two more controls: the deploy command and the switch "Ask me to look when a change gets here". "Add an entry" adds a stage (up to six) or a note that is missing, written by the owner. The group opens by itself while a probe waits for a yes, a suggestion waits, or a probe is in doubt.

Not in this change: a deploy command that Fyr runs without a press; a moment for a change that has no merged pull request.

Tests: `internal/core/playbook_test.go` (TestPlaybookSuggestion, TestStageMoments), `internal/engine/playbook_test.go` (TestStageMomentsOnTheHost), `web/test/playbook.test.ts`.
