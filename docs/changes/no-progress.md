# V0.no-progress: a live run with no tool call, no output and no turn event for 20 min is blocked in Your move

→ Amends SPEC 6.1 (the attention table's `blocked`), V0.143, V0.row-group-code; closes #448. A run that hangs (a tool that never returns, a model that says nothing) stayed Working forever: nothing told the owner it had stopped moving. The plan's M4 named this signal and it was never built.

(1) **The state.** The thread keeps its run's last progress (`ProgressAt`). At the end of every reduce, the clock's included, `noProgressAfter` (`internal/core/noprogress.go`) marks a live run silent for `core.NoProgressAfter` (20 min, the one tunable) as `NoProgress{Since, Last}`. `NextCheck` asks the clock for that moment, so the mark needs no other input. Attention puts it in Your move as `blocked`, group `unblock`, word `No progress for 20 min` and subject `last: <activity> at 14:02` (the host's local time), after an unresponsive agent and before Working. The fronts show it with the blocked row they already share (`web/src/row-ui.tsx`, `rows.ts` `blockedReason`), so desktop and phone need no change. A snooze until work is done ends on it, as on an unresponsive agent.

(2) **What is progress.** The agent's messages and tool calls and results (the digest, a subagent's too), its tasks, a turn's start, a message it took in, a tool approval it asks, any call of Fyr's tools, a slot event of its heavy job, and the CLI's own provider-wait output (`rate_limit_event`, `system/api_retry`, observed as `agent.progress`).

(3) **What is a wait, not silence.** A Bash call still running (any agent's: a build, an admitted heavy job, one the guard froze; the digest counts them), a running background task, an open ask or approval, a Run card asked or running, a merge ask held for CI or CI on the thread's PR, an armed watch, a place in the slot queue, a wait for the machine or for quota, an unresponsive or moving agent. While one lasts, the last progress moves with each reduce, and the clock is not armed; the reduce that ends it moves it once more, so the silence after a wait counts from the wait's end.

(4) **One notice.** The mark queues one `[Fyr]` line for the agent (rule `noprogress`, urgency Next): it reaches a stuck agent at its next tool call, which is the stuck one's end. It says the owner sees the thread as blocked, to stop what hangs, and to run long work in the background or as a Run card and to wait with a watch. A later clock says nothing again. Any progress clears the state (`agent.progress` event), and only a new 20-minute silence marks it again. A run that ends drops all of it.

(5) **Tests.** `internal/core/noprogress_test.go`: the mark at exactly 20 min and not a second before, the reason, one notice, the clear, each wait of (3), and a long command's end restarting the count. `internal/engine/noprogress_test.go` runs the fake agent with the engine's clock moved by hand: `stall` (a new fake word: a WebFetch that hangs until a message `release`) is blocked at 20 min, told once, and cleared when the tool returns; `hang` (a Bash `sleep 600`) stays Working for an hour.
