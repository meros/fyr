# V0.admission-tidy: a heavier second command of a thread is admitted for the difference, a job's baseline is taken at its grant, and seven smaller holes in admission are closed

→ V0.209, V0.163, V0.164, V0.admission-memory, V0.budget-restart, V0.146 (2), decision 0029 sections 0 (d), 2, 3 (rule 3, EASY) and S4.

(1) **One admission per thread.** The gate let a command through at once when its thread already held an admission. A thread (or its subagent) that held one for `go test ./...` and then started `yarn e2e` got no check. Now the gate keeps the class each hold was admitted for. A command whose class predicts more CPU or memory than that class is admitted again: its need is decided beside the other holders, without the thread's own hold, which admits the difference. When it does not fit, the thread waits in the queue as a new job does, keeps its hold for the command that runs, and hears in a `[Fyr]` message when it may run the heavier command. The grant replaces the hold, and a release ends both. A cheaper or equal second command still runs without a check, and a learned command (V0.209) still never waits. Two holders that both wait to grow would each count the other's hold and never be admitted, and "one job always runs" applied only with nothing held. So when the queue's head waits to grow and every other holder waits to grow too, the head is decided as with nothing held: the memory rules still apply. On both fronts the thread shows once. Its row stays in its group and says its job, then "waiting to grow: <why>" at the queue's head or "waiting to grow (n ahead)" behind it. The Waiting to run section has no row for it, but it keeps its place for a reorder.

(2) **Demand without a CPU stall reading.** Without the job cgroup's `cpu.pressure`, a run's demand was the cores it got, although the run's mean slowdown s was collected. It is now got × min(s, 4), as decision 0029 section 0 (d) says. A factor over 3 learns at half weight, as before.

(3) **The baseline is taken at the grant.** The tracker made the hold at the first sampler tick after the grant, up to 5 s late, and took the thread's CPU and memory then as the baseline. With V0.209 a hold lasts one tool call, so a job's first seconds went into its baseline, and a job of a few seconds learned about 0 cores. The gate now takes the baseline when it grants: the thread's cgroup read at that moment, and `memory.peak` reset then (without cgroups, the thread's last reading). The next tick makes the hold from it. A grant from the queue keeps the tick's baseline, because the agent runs the command only after the `[Fyr]` message.

(4) **A quiet heavy call is not idle.** Admission counted a hold as idle (a little CPU and the memory it holds) once nothing had been busy for 3 min, although the sweep keeps a hold with an open foreground call for up to 15 min (`HeavyCallStale`). A test waiting on a server lost its predicted need to the next admission. While the thread has a heavy call open, admission counts the prediction. The engine publishes the open calls without a lock, because admission reads them under the pool's lock.

(5) **The AIMD controller reads the configured reserve.** It judged memory short against the default 10 % reserve, not the host's `slotMemoryReserve`. It now gets the policy admission uses.

(6) **A holder's undeclared flag is not counted twice.** A thread just admitted keeps its undeclared-work flag until the detector's next reading. Admission added that flag beside the thread's held need when it decided about other jobs. A holder's own flag is now left out, because its held need already stands for that use. A service's reservation still counts.

(7) **A new job asks the head first.** A job that joined a queue whose head fits now (the host freed room since the last fill) was backfilled past the head and used one of its three passes. The new job now promotes the queue first, then backfills.

(8) **Not changed: a finished background job's need.** It is kept until the 2 min `SlotIdle` sweep. To release it at the next tick, the sweep would need a new dependency that says the job's cgroup is empty. That cgroup is the guard's code, and a detached command (`nohup`, `&`) is not tied to a task Fyr sees. It is left for a later change.

(9) **Page cache that is read back is not headroom.** The headroom counts the agents' working set as `memory.current` − `inactive_file` (V0.146 (2)). On 19 Nov 16:02 it read 48 % while the agents sat at `memory.high` with a critical full stall: the inactive file pages were refaulted as fast as the kernel dropped them. The sampler now reads `workingset_refault_file` from the agents' `memory.stat` and takes off only the inactive cache that is not read back within 10 s at the rate since the last read. The first read, a gap of over a minute, or a kernel without the key takes off all of it, as before.

(10) **The pause notice no longer says to ask.** The notice for paused undeclared work ended with "Ask with mcp__fyr__slot_acquire before a heavy job.", although V0.209 admits a heavy command by itself. The sentence is gone.
