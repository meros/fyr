# V0.app-shell-tidy: answering lives in useAnswers, settle, archive and snooze leave only once the host took them on both fronts, and the shell's hooks say what they hold

→ V0.web-review-fixes (5, 6), V0.settle-leaves, U8, V0.114. *Amends V0.settle-leaves (1) ("Archive and snooze are unchanged": they now leave as a settle does) and U8 (the phone's snooze leaves the open thread too).*

A review of the web client's shell, after it was split into `app-*.tsx` hooks, found answering kept in the context-menu hook, a different rule for leaving a thread per action and per front, the phone's search computing again what the shell had computed, the same providers nested twice, and headers copied from the old `app.tsx`.

1. **Answering in `useAnswers`** (`app-cards.tsx`). The answer, cancel and allow commands, the desktop's walk on to the next thread (`submitAsk`, `nextNeeding`) and its answer field moved out of `useContextMenu`, which keeps only the right-click menu and the desktop's way to run a thread action. Both fronts change the question card with one updater on the card as it is now (`onCard(fn)`, `updateCard` in `question.ts`); the desktop's card took a value built from the last render, so two changes in one tick lost the first.
2. **One rule for leaving.** A settle, an archive and a snooze let the thread go only once the host took the command (`leaveAfterHost`, `web/src/leave.ts`, with `ThreadCommands.took`, the ids the host took): a refused one leaves the owner where they were. Before, the desktop's archive and snooze stepped past the row first, and the phone's snooze never left. Where the screen goes stays each front's: the desktop opens the next row or the status screen, from the list and the thread pane alike (`afterSettle`, now for all three, read at the time the host answered, so an owner who moved on meanwhile stays where they went); the phone goes back to the inbox (`leaveOpenThread`, which also checks that the open thread is the one that left).
3. **One search.** The phone's search screen reads the shell's query, search list and quiet-hits count (`app-state.tsx`) instead of computing them again. The phone has no search box on its inbox, so the query lives while the search screen does and is cleared when it goes. While it is typed the counts follow it, as on the desktop.
4. **`AppProviders`** (`app.tsx`): the seven contexts both fronts read are nested once.
5. **Headers and aliases.** Each `app-*.tsx` file says what it holds; the copied "The app shell" header and a toast timer that `app-cards.tsx` does not have are gone; `app-state.tsx` has no `rows = liveRows` or `drawn = sec` alias.
6. **Tests.** `web/test/leave.test.ts` (nothing moves before the host answers, a refused command moves nothing, only the ids taken leave); `web/test/question.test.ts` (`updateCard`: two changes in one tick both land, a closed decision's card stays absent).
