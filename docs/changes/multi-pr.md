# V0.multi-pr: a thread or change that opens many PRs tracks every one of them

→ 3.13, V0.36, V0.43, V0.59, V0.98, V0.row-calm. *Amends V0.43 (PR tab and commands read only the main PR), V0.36 (`thread.dismissPR` dismisses only the main PR), V0.98 (6) (one header PR chip).* Work in one thread often opens several pull requests (across repositories, or stacked). Previously only `mainChange` reached the PR tab, inbox chip, header chip and PR commands, and a second PR from one command or attached to an existing change could be missed.

1. **Capturing every PR.** `gh pr create` digesting reads every canonical PR URL printed on its own line (in order, deduplicated), not only the last. `change_open` with `pr` adds the PR's repository target and skips joining a branch change that already owns a different PR, and observes the PR immediately so the second and later PRs enter `review` with built-in actions armed. Attaching a `pr` evidence URL on `change_update` that differs from the change's PR also creates and tracks its code change. The poller trigger (`OnPR`) fires whenever a thread gains any new non-dismissed PR URL, not only the first.
2. **Per-PR detail and commands.** `GET /api/threads/{id}/pr` takes an optional `?pr=<url>` or `?change=<id>` (resolved only among the thread's own changes), defaulting to the main PR or newest non-dismissed PR. `pr.merge`, `pr.rerunFailed` and `thread.dismissPR` take an optional `pr` or `change` argument to act on that PR; `Available` checks across all non-dismissed PRs of the thread. Dismissing the main PR promotes another non-dismissed PR (preferring an open one, newest first) to `mainChange`.
3. **Inbox rows (desktop and phone).** The row PR badge shows the most urgent open PR (failing > conflicts > changes requested > review required > ready > running), with `+N` when more open PRs exist (for example `#101 failing +2`), and lists every PR in its tooltip. When no PR is open and no non-PR change chip applies, it shows non-dismissed merged or closed PRs the same way. `stateNamesPr` does not hide the chip while more than one PR is represented so the `+N` count stays visible.
4. **Thread header chips (desktop and phone).** The header shows one chip per open (not done, ended or dismissed) PR, prefixed with the short repository name when the PRs span multiple repositories. Clicking or tapping a PR chip opens that PR directly in the PR tab (modifier clicks and right-click keep the GitHub link on desktop). Merged or closed PRs drop out of the header chips once open ones exist or the change is done, while staying reachable in the PR tab until dismissed.
5. **PR tab (desktop and phone).** The tab bar keeps one tab, labelled `PR` for one non-dismissed PR and `PRs (N)` for two or more. Inside the PR tab, a switcher strip above the header lists every non-dismissed PR (open first, then merged/closed until dismissed), with the short repo name when multiple repos are present. Switching PRs loads its detail, checks, reviews, comments, Merge, Re-run failed and Dismiss PR independently. Phone Peek shows the urgency badge (`+N`), and Details lists every non-dismissed PR.
