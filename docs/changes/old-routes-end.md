# V0.old-routes-end: the front serves a host's calls by its install id and its own under /api/front/, and nothing else; there is no default host

→ decision 0031 slice 5 (2.2, 2.8, test 2), V0.172, V0.client-refs, V0.client-per-host, V0.row-group-code. *Ends V0.172 (6) (the old routes, marked `Deprecation: true` and counted in `oldRouteUses`); amends V0.51, V0.54, V0.127 and V0.132 where they let a call name its host by name or name none (`args.host`, `?host=`, `?thread=`, the first host in the owner's order).* (decision 0031)

Slice 4 has been in every release since 19 Nov, so the client of the last release names every host by its id. The old routes and their fallbacks go.

(1) **Two prefixes and nothing else.** The browser API is `/api/h/<hostId>/…` (one host, by install id) and `/api/front/…` (the front's own: state, stream, command, presence, push, auth, peer). Every other `/api/` path is `404 {"ok": false, "code": "no-route"}` and reaches no host; an unknown id is `404 no-host`, as before. Gone with them: the merged `/api/state` and its stamps (`host`, `hostOffline`, the raised revs), `/api/stream`, `/api/command` and `args.host`, `/api/threads/…` by the thread's id, `/api/attachments` and `/api/previews/…` with `?host=`/`?thread=` and the ids the front learned (`objs`), `/api/projects/{id}/…` by the project's id, the merged `/api/quota`, `/api/load` and `/api/profiles` (`gather`), the settings reads by `?host=`, `/api/presence` by thread id, and the `/api/push/*`, `/api/auth/*`, `/api/peer/*` copies of the front's routes. Inside the front `byName`, `owner()`, `target()`, `isLocal` and the first host as a default are gone; a call that needs a host names it by id, and a missing id is an error.

(2) **One stream.** The old stream's hub is gone; `/api/front/stream` carries every host's frames with `host: <id>`. A host's `project`, `deploy` and `stall` frames now go on it too (they went only to the old stream, so a client of slice 2b missed them until its next reload); every host's `deploy` goes out, and the client's banner is the one of the host the front runs in (decision 0031 2.6). The front's cache file no longer keeps the stamped copy (`pub`).

(3) **The client's fallbacks.** The device no longer moves `fyr.draft.<id>`, the filters and New thread's defaults from bare ids and names to refs (`storage-migrate.ts` is gone; the rotation of a host's id stays, in `host-rotation.ts`), no longer reads a draft under the bare id, and no longer removes `fyr.hostFilter`. The stale IndexedDB `state2` entry is deleted when the per-host copy is written. A thread's host key is its install id (no name fallback in `filters.threadHostKey` or `hidden.ts`). `stallsOf`/`upsertStall` and `StateDTO.host`, `hostId`, `machine`, `stalls` (the merged state's fields) are gone. A row without the host's group code (V0.row-group-code) is Unblock and its reason is shown as sent: the words are no longer read (`legacyNeedsGroup`, `legacyBlockedReason`). An old deep link or push tap (`?open=<threadId>`) still opens the one thread that has the id (C12).

(4) **Kept.** `legacyFronts` and the `legacy` principal (`HowLegacy`): a front of an older build that sends no `Fyr-Actor` on the whois listener is still served in the peer way's observe mode, and a front with no session store names its caller so. They end with the whois listener (decision 0030), not with these routes.

(5) **Tests.** Decision 0031 test 2 whole (`TestNoDefaultHost`, `internal/front/hostprefix_test.go`): every pattern of the front's mux is a host's by id, the front's, or not the API; each old path, by GET and POST, is 404 `no-route` and reaches neither fake host; an unknown id is 404 `no-host` and reaches none. The hop table lists only the new routes. The front's tests and `internal/authtest` speak the two prefixes; the front tests read a host's state as the client does (`/api/front/state`, then `/api/h/<id>/state`).

**Test wait (`TestProjectSharedFromAHost`).** The `projectOn` helper waited until `/api/h/<id>/state` showed the new project. For an online host that read goes straight to the host. A project link, though, resolves the ref in the front's own copy of the host's state, which the host's stream fills a moment later. Once the old merged `/api/state` was gone, CI hit that gap once ("a has no project …", 404). The test passed 30 times alone and 30 times beside four busy loops. The helper now also waits until the front itself resolves the ref (`frontKnows`). It is a race in the test's wait; the product code is unchanged, because the UI offers a project only after the front's stream has carried it.
