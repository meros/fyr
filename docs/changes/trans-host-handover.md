# V0.trans-host-handover: hand a thread over to another host as a linked new thread

→ Decision 0039, amends V0.45 (decision 0013) and SPEC 5.3 / 10.4.

A thread can now be handed over across hosts from the same "Hand over…" dialog/sheet on desktop and phone (when more than one online host exists):

1. **Front orchestration (`front.threadHandover`).** Both hosts must be online. The front exports a bundle from the source host (`POST /api/threads/{id}/handover/export`), imports it on the target host (`POST /api/threads/handover/import`), and only after the target succeeds records `thread.handedOver` on the source host (setting `handedOverTo`, appending a handover divider, and settling the source thread). A failed import leaves the source thread untouched.
2. **Copied history and bidirectional links.** The target thread keeps a copy of the source thread's conversation events (up to 2,000 newest lean events) and any open main PR, carries `handedOverFrom`, and renders a handover divider linking back to the source thread. The settled source thread carries `handedOverTo` and renders a handover divider and header link to open the target thread.
3. **Same 3-rung ladder across hosts.** When the CLI family matches, the export includes a bounded tar.gz archive (max 20 MB) of the CLI session files; the target extracts it under its own project directory for `--resume` (rung 1), falling back to Adopt with the exported conversation Markdown (rung 2), or asking the source host for a Brief (rung 3).
4. **Git limitations and injected host-move context.** `GET /api/threads/{id}/handover` adds `cli` and `git` (repo, branch, default, head, ahead, unpushed, dirty, worktree). The handover dialog informs the owner about uncommitted files, unpushed commits, and local state staying on the source host without modifying git. The target thread injects a `[Fyr] Host handover:` notice naming source/target hosts, folders, branch, dirty/unpushed counts, worktree outcome, and open changes (queued into `Feed` with urgency `next` on rung 1; included in the handover message on rungs 2 and 3).
5. **Target folder and worktree resolution.** The UI pre-selects the target host's linked project folder (decision 0034) or a project with the same git `origin` remote, lets the owner override with the target host's folder picker (or start a scratch folder), and optionally creates or reuses a worktree for a non-default branch when present locally or on `origin`.
