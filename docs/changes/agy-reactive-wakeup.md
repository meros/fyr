# V0.agy-reactive-wakeup: Settle agy reactive-wakeup turns, track background tools, and refresh Thinking status

→ V0.agy-adapter, V0.16, V0.21, V0.133.

When an `agy` agent starts a tool that moves to the background (such as a shell command that runs past `WaitMsBeforeAsync`), `agy acp --stdio` answers the in-flight `session/prompt` RPC with `stopReason: "end_turn"` while that tool is still in progress. When the background tool later completes, `agy` sends `tool_call_update` and wakes the agent automatically for a follow-up turn without a `session/prompt` request from Fyr. Because no RPC is in flight, `agy` streams the reactive turn's thoughts, tool calls, `agent_message_chunk`s, and final `usage_update`, then stops without sending a JSON-RPC `stopReason` response. Before this change, Fyr left those threads stuck in `Working` on their last tool's activity indefinitely, held their final assistant reply unflushed (and discarded it on the next prompt), failed to track backgrounded tools across turns, and left `Activity` showing a completed tool while the model thought.

(1) **Settling unsolicited and reattached reactive turns (`internal/cli/agycli`).** `acpSession` tracks unsolicited turns separately from prompted turns (`turnRunning`). When `usage_update` arrives outside a prompted turn with buffered assistant text and no open permission request, `promptWorker` arms a short settle window (1.5 s, cancelled by any subsequent `tool_call`, `tool_call_update`, `agent_thought_chunk`, `agent_message_chunk`, `session/request_permission`, or reattached JSON-RPC `stopReason` response). When the window expires, `acpSession` flushes the buffered assistant text, emits `result`, and releases any queued user prompts. A fallback window on `agent_message_chunk` handles unsolicited turns that end without `usage_update` (such as quota notices), and `Interrupt` (`session/cancel`) settles an unsolicited turn as `interrupted` when no JSON-RPC response arrives.

(2) **Background tool tracking across turns (`internal/cli/agycli`).** Tools still open when a turn ends normally are promoted to `bgTools` and reported via `background_tasks_changed` and `task_started` so the thread shows its background wait and `Manager`'s idle timer does not stop the process while background work runs. Their IDs remain in `emittedTools` across turn boundaries to avoid duplicate `tool_use` emissions, and their later `tool_call_update` completion emits `task_notification` and updates `background_tasks_changed`.

(3) **Live Thinking status (`internal/cli/agycli`, `internal/agent`, `internal/core`).** When an `agy` reactive wakeup begins thinking (`agent_thought_chunk` while idle), `acpSession` emits a single `thinking` assistant message so Fyr opens the run immediately instead of waiting for the first tool call. `digest.feed` tracks open top-level `tool_use` IDs and reports `Activity: "Thinking"` once all open tools have returned their `tool_result` (and on top-level `thinking` blocks when no tools are open), while `KindDigest` updates `Thread.Activity` only when `Thread.Running` is true.
