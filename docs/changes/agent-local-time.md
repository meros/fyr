# V0.agent-local-time: the agent prompt names the owner's time zone and asks for local time

→ Amends V0.12 and V0.prompt-fits-setup. An agent has no way to know which zone the owner reads times in, so it wrote UTC, or guessed, in reminders, watch notes and schedules. `agent.Setup` now carries `Zone`, read from the host when the process starts (`agent.ZoneLabel`: the IANA name from `time.Local`, `TZ` or `/etc/localtime`, with the abbreviation and the current UTC offset, for example `Europe/Stockholm (CET, UTC+01:00)`). `Prompt` adds one line: the user's time zone is that, use local time in everything the user reads and when reading a time the user gave, unless there is a reason not to (a protocol that wants UTC or an offset, a log already in UTC), and say which zone when a time is ambiguous. A setup with no zone adds no line. The zone is the host's, which is the owner's for a local daemon; a remote host's zone is that host's.
