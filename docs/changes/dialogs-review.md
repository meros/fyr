# V0.dialogs-review: New thread starts with the prompt and keeps what was typed as a draft that says what it is, Back and Esc go one level up, no key acts under an open dialog, and a thread's actions and a merge look the same wherever they start

→ V0.26, V0.30 (4), V0.31, V0.42, V0.45, V0.61, V0.63, V0.67, V0.68, V0.72, V0.97, V0.121, V0.139, V0.185, V0.one-action-list, V0.sensitive-pr, V0.composer-focus-reach (2), V0.trans-host-handover. Amends V0.26 (the thread's ⋯ menu no longer starts with Project…), V0.61 (what Enter does in the project search), V0.63 (what closes the New project step), V0.185 ("until work is done" is the last preset; the date and time comes after it on both fronts, as it did on the phone) and V0.sensitive-pr (a sensitive merge asks in the Merge dialog).

Why: a review of every dialog, sheet and menu outside Settings, run against the built client on both fronts, found work that could be lost and keys that acted in the wrong place; a second review of the result found that the restored draft was a hazard of its own, that the same thing looked different depending on where it started, and that the phone's Back layers were right only in the orders they were written for. The numbers in brackets are the first review's findings.

- New thread asked for the prompt last, under five fields that keep their defaults, and on a 720 px window one line of it showed. Esc, a click beside the dialog or × threw the whole form away, from the project list and the New project step too.
- With the Merge dialog open, `#` archived the thread behind it and `s` opened Snooze on top of it: the app's key handler knew only the dialogs it opens itself.
- On the phone, Back with the folder picker, a confirmation or the New project step open left the screen under it; the folder picker then stood over the inbox.
- Enter in the project search made a project named like the typed part of an existing project's name.
- Errors of New thread were printed below the visible part of the dialog.

(1) **New thread, one form on both fronts.** The order is: the prompt (no label; placeholder "What should the agent do?", "Add a note (optional)" with a file), the attach row, Host (only with several hosts), Project, Folder, Agent, and a fold "More" with Title and Live view. The desktop dialog and the phone screen have the same fields, order and words; the state is one hook (`web/src/new-thread-form.ts`) over one pure model (`web/src/new-thread.ts`).
- The prompt has the focus when the desktop dialog opens, and again after a project or a folder is picked and after a project is made (9). It grows with its text up to 40 % of the window's height, then scrolls (18).
- The Host field has no standing help line here; its help is the label's tooltip, and an offline host's note still shows under it.
- The Folder line has a hint only when the hint says something the Project field does not.
- More is open when Title or Live view has a value, and its summary says what it holds: "More: title, live view" while nothing in it is set, else what is set ("More: Live view on"), so a closed fold never hides a value. Live view's help is text beside the box, not a tooltip. Enter in Title starts the thread, as in the prompt (17), on both fronts.
- The Folder row reads "The project's folder" when the thread simply starts there (the Project row above shows the path), and a path only when another folder is picked.
- ⌘⏎ or Ctrl+⏎ presses the primary button from any field of the desktop dialog.
- The form's foot (desktop) and bottom bar (phone) hold what must be seen without scrolling: the error of the last try (`role="alert"`), the New project step's own errors too, else why Start is off; and Discard while the form holds something. The focus goes to the field the error is about (5). The desktop's second button is "Close", not "Cancel": what was typed stays as the draft.
- Start is off while there is nothing to send or the host cannot take the thread, on both fronts, with the reason beside it (23): "Write a prompt or attach a file.", "lab is offline since 19:40.".
- A dialog stands 6vh from the top and is at most 88vh tall (it was 12vh and 76vh). Settings keeps its size and place.
- The picked provider's quota stands under Agent on both fronts. It shows from the first opening (a quota read that landed between the form's first render and its subscription was missed until the next minute).
- The phone differs where touch or width forces it, each with its reason at the code: no focus on open and no return of the focus (a focused field raises the keyboard); Enter in the prompt is a new line (no modifier key); four attach buttons, Paste, Camera, Photos and Files, in one row where the desktop has a paperclip and "Paste or drop files" (no drop on touch, separate system pickers); More also holds every provider's quota, and its summary says so (no rail that shows the others); "Add … on …" is 44 px high; no ⌘⏎.

(2) **One primary button (11).** While the New project step is open, Start reads "Create project and start", and the step's own "Create project" is a plain button. Enter in the step's Name does what that one primary button says; while there is nothing to send yet the button is off, and Enter makes the project, as the step's own button does.

(3) **The New project step in New thread.**
- Its folder field is labelled "Project folder" (13), also in Settings and in the Project picker, which share the step. While the step is open the thread's own Folder row is hidden, and one line above the step's buttons says where the thread starts, about the project being made (6): "Zebra is new and has no folder: the thread starts in a fresh scratch folder." The Name field's placeholder is "Name", and an empty name marks the field.
- What is typed in it stays while New thread is open (12): Back shows the project list again with the name in its search, the Project button closes the step, and both keep the name and the folder for the next time the step opens. Another host keeps the step open with its name; its folder, and a folder picked for the thread, are paths of the other host and go, and a line under Host says what went. Only making the project ends it. This amends V0.63, where Cancel and the Project button dropped it. The Project picker (file a thread) keeps the step's name and folder in the same way, and there too Esc in the step goes back to the list before it closes the dialog.
- A look at another host and back keeps the project and the folder the owner picked by hand on the first; the project a change of host assigns is not counted as the owner's pick, so the line under Host never blames them for it.
- A button that adds a project on another host names that host, not its install id (7).

(4) **Nothing typed is lost, and a draft says what it is (3).** What the owner put into New thread is a draft: the prompt, the title, Live view, the New project step's name and folder, the picks made by hand (host, project, folder, provider, model, effort), and how many files were attached. It is kept in this browser's storage under `fyr.newThreadDraft` a moment after the form changes and at once as the form closes or the page goes, so every way of closing the form keeps it (Esc, the dimmed area, ×, the phone's Back and ×, a reload). A started thread removes the draft. Picks alone are not a draft: without a word typed or a file attached the form opens on its defaults.
- The next New thread opens with it, and a line above the prompt says what it is: "Draft from yesterday 16:40 · in acme/web · Discard", with × to hide the line. The line goes with the first change the owner makes: from then on the text is simply the form's.
- The first Enter on a draft nobody touched does not start it; the foot says "This is the draft, unchanged. Press Enter again to start it." A press of the button starts it.
- Discard empties the form and forgets the draft; the line then reads "Discarded · Undo" until the next change, and Undo puts the form and its files back. Discard is also in the foot whenever the form holds something, so a prompt started in error can be thrown away without the mouse on a restored line.
- A draft does not move the form from where it was opened. Opened from the inbox filtered on a project, the form stays on that project and its host; a provider or a folder picked on another host is dropped. The one exception is a project picked by hand in the draft: the form goes to it, and the line says so ("in acme/web, the project picked in the draft"). A draft's project that is no longer offered leaves the form's own, and the line says that. A host picked by hand moves the form only when no filter chose the project. A quiet project the draft was written for is offered again for it.
- The New project step comes back closed: its name is in the project list's search the first time the list opens, and its folder is kept for the step. No restored form has a primary button that makes a project.
- Attached files: an upload is a file on the host and a chip in the page. The files of a closed form come back with the draft while the page lives and the form starts on the host they were uploaded to. What cannot come back is said, never pretended: after a reload, on another host, or for an upload that was still on its way, the line says "2 files were not kept". A form of files alone is a draft too. Closing it while a file is still uploading asks first on the desktop and from the phone's × ("A file is still uploading. It is not kept when you close now."), and the browser asks before a reload of a form of files alone. The phone's system Back cannot ask; the line says what was not kept.
- A pick that no longer exists (a project, a provider, the host) leaves the form's default; a draft whose host is gone keeps its words. A pick the owner makes while a stored draft's picks still wait for the host's state wins over them. A second tab that starts or discards the draft stops this tab from writing it back until the owner changes the form here. A thread that fails to start after "Create project and start" made the project keeps the draft with that project picked, so a reload does not make it twice.

(5) **Esc and Back go one level up.** In New thread Esc closes, in this order: the `/` list, the New project step (to the project list), the project list, the dialog. On the phone Back does the same for the step and the list; the header's × leaves the screen in one step. In Snooze, Esc (desktop) and Back (phone) fold the date and time field back to its row before they close the dialog.

(6) **The phone's Back closes the top-most layer (4).** The folder picker, a confirmation, a dialog shown as a sheet (the Merge dialog), the diff comment sheet, Snooze's date and time field, and the project list and New project step inside New thread and inside the Project sheet are layers: each has a history entry of its own while it is up, with the screen's own state and URL, so Back closes it and the screen under it stays (`web/src/back-layer.ts`).
- One rule holds it: a layer's entry says how many layers lie over the screen there, and on every popstate that number is compared with how many layers are open. Fewer in the history: the owner went Back over layers, and those close. More: entries are left over (a layer closed on the page, Forward onto a gone layer's entry, a reload over a layer), and the stack steps back by that many. The same: nothing. So another module's traversal (the full-screen view) is never taken for the owner's Back, and the full-screen view leaves only when its own entry was left.
- The phone's history is built by whoever needs it first, a layer that is up in the first render or the navigation, so a layer's entry never lies under the seeded entries. A page loaded on a layer's entry keeps the entries under it.
- A navigation closes the open layers on the page and waits until their entries are out; it runs in a turn of its own after the popstate event, so it does not depend on which listener the browser calls first. A Back control of the page (the header's arrow or ×, a sheet's close) steps over the layers of what it leaves and closes them. No layer stays on the screen without its entry. Each traversal has its own give-up timer.

(7) **No app key acts under an open dialog (1).** The desktop's key handler returns while a modal panel is open that its `dialog` state does not know, and while a second panel is open over a dialog. It reads the focus trap's stack, which every dialog joins, so a later dialog cannot forget it. The Merge dialog's Esc and Enter are its own. Esc that closes the folder or quota popover goes no further (21): it no longer also interrupts the run or closes the thread.

(8) **The first focus of a dialog is not its × (10).** The focus starts on the first control that is not the header's ×: the first choice in Snooze (the arrows walk the choices; from the × Down goes to the first and Up to the last), the search in Changes, and "To" in Hand over.

(9) **Enter in the project search takes the best match (2).** *Amends V0.61.* Under typed text the matches come first, in the owner's order (V0.121), and "New project “text”" after them. Enter takes the project of the list whose name answers the text best: the exact name, else a name that starts with it, else a word of the name (the whole word before the start of one), else a name that contains it; the earlier one when two answer alike. That row is marked with ⏎, so "infra" visibly means acme/infra and not a longer name that contains it. Enter starts New project only when nothing matches, where that row is the only one, and never takes a project that is not in the list (another host's). V0.61 had Enter make a project for every text that was not an exact name. With an empty search the New project row stays first (V0.30). The picked project is scrolled into view when the list opens. A row's number of threads says so in its tooltip. On the phone the Project sheet does not focus its search (14): the focus raised the keyboard over a list whose usual use is one tap. The Project dialog and sheet name the thread they file under their title.

(10) **Snooze: a date and time of the owner's own on both fronts (15).** The last choice is "Pick a date and time…" (desktop key `t`). It opens one field, labelled "Date and time", that starts on tomorrow at the hour "Tomorrow morning" means (06:00) and takes no time before now. Why its button is off is text under the field on both fronts ("Pick a time after now."), not a tooltip. The dialog and the sheet are titled "Snooze" with the one thread's title under it; the phone's list has no Cancel row and no icon per row.

(11) **Hand over (16).** The dialog is wide. Across hosts the button reads "Move to <host> and settle here", and the sentence above the form marks "and settles this thread". How the context goes over stands between the form and the buttons, outside the part that scrolls, as text with its label ("Context: …"), not in a box that looks like a control. The thread's own host is marked "(now)" in the Host tabs. The same model on the other side is not a change: the line reads "Keeps Opus 5.5 · effort high". With the picked host offline nothing is promised: no provider choice, mapping or plan shows, and the reason stands beside the disabled button. Enter confirms and the foot names Esc and Enter, as in the confirmation; not on the phone, which has no keyboard, where the two buttons centre their words like every other sheet's (30).

(12) **One Merge dialog (27).** Every merge that asks first asks in the same dialog, on both fronts (`web/src/merge-ui.tsx`): the PR tab's "Merge…", a change card's Merge, the inbox row's Merge and the agent's merge ask. Its title names what is merged ("Merge #4170", "Merge #212, a sensitive PR") and the PR's title stands in it. It starts on the method the repository was merged with last on this device (`fyr.mergeMethod`), stays open with the host's refusal, which has a line of its own above the buttons ("Not merged: …"; beside them it was one letter wide on the desktop), and names Esc and Enter in its foot on the desktop. A sensitive merge is red and starts with the focus on Cancel. A plain merge from a card's need strip or the agent's ask goes at once, as before.
- The method choice is offered where the host takes one: the PR tab, which sends `pr.merge`. A card's Merge and an answered merge ask run `action.run` and `thread.answer`, which take no method, so the dialog says there that the change's own method is used and that the PR tab lets the owner pick one. It offers no choice it could not keep.
- A change card has one Merge button: the need strip's. The merge offer has no second button in the action bar while the strip offers it; the strip's button carries that merge's state (running, failed), and its output stays one press away.

(13) **One list of a thread's actions.** The row's right-click menu, the thread header's ⋯ menu and the phone's thread sheets show the one order and the groups of `web/src/actions.ts`, with a line between groups; Archive is last, apart from Mark seen. *Amends V0.26*, where the ⋯ menu started with Project…. The desktop's two menus share their rows: the key at the right, and under an entry that is off the reason why. A key shown beside an entry runs it while the menu is open; "↵" and "Esc" are not shown there, because in a menu they take the focused entry and close it. The phone's selection sheet offers Settle, Snooze…, Project… and Archive for the picked threads, as the desktop's selection does (31).

(14) **Confirmations.** A red confirmation names what it acts on ("End “Promote to production”?") and starts with the focus on Cancel, so an Enter on its way elsewhere cancels; its button shows no ⏎. A held Enter that repeats into a confirmation is not an answer to it.

(15) **One word for one thing (26).** The folder picker's button is "Change…" everywhere. New thread's button is "Start" and its key hint "start". The prompt says "the agent", never a provider's name; the phone's peek names the thread's provider. A thread without a folder of the owner's starts in "A fresh scratch folder" in New thread and Hand over. Hand over's texts use ":" where they had a dash.

(16) **Smaller.** The card's link and the confirmation's button both say "End change", which is red like the other confirmations that cannot be taken back (28); the Project picker's button says "Create and file these threads" for several; why a tap beside a confirmation cancels on the phone and does nothing on the desktop is written at the code. The phone's Details shows the folder short ("~/…") and the host with several hosts (29). A row of the phone's thread sheet that is off names no swipe. `&dialog=handover` and `&dialog=picker` open the open thread's Hand over and Project dialogs, and `web/NOTES.md` lists the links that exist (32).

Not in this change: a key or a button for Hand over (32); a method choice for a merge that starts on a card or an ask (the host's `action.run` and `thread.answer` take none); an icon on every row of the phone's thread sheet; Project before Host in New thread; Start that waits for uploads.
