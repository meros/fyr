# V0.new-thread-skills: New thread has a Skills button that lists every skill and command, a scratch folder lists the provider's newest, and the phone's list is no longer a sliver

→ V0.79 (2), (3). Starting a thread with a skill did not work on the phone, for three reasons. On the phone's New thread the `/` list was a flex item of the scrolling form, and its own `overflow` let it shrink to a few pixels: the list opened, but nothing could be seen or tapped. A thread in a scratch folder (the default without a project), or in a folder no session of the provider had started in, had no list at all, since the host keeps one per provider and folder. And `/` is on the second page of a phone keyboard, so even a list that worked was a hunt to open.

1. **Served.** The host also keeps the newest non-empty list of each provider, from any folder. `GET /api/commands?cwd=&profile=` answers the folder's list, else (no `cwd`, or a folder none was seen in) the provider's newest, else none. A thread's `from: "folder"` follows the same rule. The user's own skills and the CLI's commands are the same in every folder; only a folder's project skills differ, and the CLI says so when a picked one is not there.
2. **Skills button.** New thread has a Skills button: on the phone a fifth tile in the attach row (Skills, Paste, Camera, Photos, Files), on the desktop a small button at the end of the attach row. A press opens the same list above the prompt with every command and skill by name, not capped at 8: it scrolls. Typing `/name` while it is open filters it as before. A pick puts `/name ` before what the owner typed (a command typed before is replaced: only the first word runs as one). A second press, Escape or a pick closes it. A provider with no list yet says "No skills seen for this agent yet: they show once a thread of it has started." The phone's tile does not focus the prompt (the keyboard would cover the list). The desktop's button returns the focus to the prompt, whose arrow keys, Tab and Enter work in the list as for a typed `/`.
3. **Never interrupts.** The list opens only from the owner's press or their typed `/`. The list fetched in the background replaces nothing the owner typed.
4. **The phone's list** keeps its height (`flex: none`) and scrolls inside its own max-height.

Tests: `internal/server/commands_test.go` (no folder and an unseen folder list the provider's newest; an empty list does not replace it); `web/test/slash.test.ts` (every command by name, a pick before the typed text); `web/test/layout.e2e.mjs` (V0.new-thread-skills: the tile, the list's height and rows on a 360 × 640 phone, a tap fills `/review fix the login bug`).
