# V0.desktop-chromium: the Linux app's window is a bundled Chromium app window that the app drives over a DevTools pipe, instead of WebKitGTK

→ amends V0.linux-desktop and decision 0038 (the shell, the window, the bridge, packaging); replaces V0.desktop-no-dmabuf and V0.desktop-gpu-shm; keeps V0.desktop-popup-links' rule with a new mechanism.

Why: WebKitGTK could not both draw the page fast and keep it from flickering. With its DMABUF renderer off (V0.desktop-no-dmabuf) it paints every frame on the CPU, about 90 ms of CPU a keystroke with many threads. With it on, even over shared memory (V0.desktop-gpu-shm), the window flashed while the owner typed. Its script engine also runs the web client slower than a browser does. The same page in Chromium draws on the GPU, never flashes, and types at about 15 ms a key with the same threads.

1. **The window** is Chromium started by `fyr-desktop` as `--app=<Fyr's origin>/` with its own profile (`~/.local/share/fyr-desktop/chromium`), driven over `--remote-debugging-pipe`, so no debugging port is opened (`internal/desktop/chrome.go`, `cdp.go`). Its app id is `chrome-fyr.localhost__-Default`; the `.desktop` file's `StartupWMClass` names it, so the dock shows Fyr's icon.
2. **Hooks before the page.** When the window's page attaches, the app adds the `fyrPush` bridge script, its binding and the request hooks, and only then loads the page it wants. That cancels the `--app` load that started meanwhile, so no Fyr page runs without the bridge, and a one-time link is never spent on a request that is thrown away.
3. **The bridge** is `window.webkit.messageHandlers.fyrPush`, as in WKWebView, made before the page's own scripts. The app answers only a call from the window's main frame on Fyr's origin; a frame (a preview, served on the same origin) gets no answer.
4. **Sign-in, failures, links:** a main-frame 401 asks the owner socket for a link (at most once in `Signin`'s gap) and the signed-out page is not shown; a main-frame load that fails shows the offline page or signs in again; a main-frame navigation off Fyr, and a window a page opens off Fyr, go to the default browser (`External`, `ChildWindow`).
5. **The user agent** is a launch flag built from the binary's `--version`: Chromium's reduced user agent with `FyrDesktop/linux` after it, so it holds from the first request. The web client registers no service worker when it sees `FyrDesktop/` (`isDesktopApp`, `web/src/pwa.ts`), and the app clears any service worker of Fyr's origin from the profile when the window opens.
6. **Close, open, quit:** closing the window ends Chromium; the tray and the notifications stay. Open (the tray, a second start, a click on a notification) starts it again on the page it showed last, or on the notification's thread. Quit closes it. The size is read from the window every 2 s and restored at the next start.
7. **Packaging:** the flake's `fyr-desktop` depends on nixpkgs' `chromium` (the path is built in with `-X main.chromium`) and no longer on WebKitGTK or glib-networking. A build without that path uses `-chromium`, else `chromium`, `chromium-browser`, `google-chrome-stable` or `google-chrome` on `PATH`.

Checked in a headless sway with the built binary, a throwaway `fyrd` and its own session bus: sign-in by a link, sign-in after a 401 with browser auth enforced, the user agent, the bridge's answer, no service worker, the page on the GPU (ANGLE on Mesa), the app id, close and open again, and quit leaving no Chromium behind.
