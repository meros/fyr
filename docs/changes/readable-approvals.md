# V0.readable-approvals: human-readable tool approval cards, inbox rows and push notifications

→ Amends V0.20, V0.27, V0.row-calm and V0.notification-polish. Tool approval cards previously showed raw tool IDs such as `Allow mcp__fyr__offer_action?` and dumped non-command arguments as raw `JSON.stringify` clipped to eight lines. Like effect cards (V0.27), approvals now lead with plain language and structured fields while keeping the raw tool call behind `Details`. The Go side mirrors the web formatter by hand, so the owner reads the same words in the inbox, on the card and on a lock screen; a wording change belongs in both `approvals.ts` and `notify.go`.

1. **Shared formatter (`web/src/approvals.ts`).** `describeApproval(decision, cwd)` maps built-in tools (`Bash`, `Edit`, `Write`, `Read`, `Grep`, `Glob`, `WebSearch`, `WebFetch`, `Agent`, `Skill`), Fyr MCP tools (`offer_action`, `run_request`, `ask`, `settle_request`, `watch`, `change_*`, `show`, `view_*`, `thread_*`, `keep_process`, `*_setup`), and arbitrary external MCP tools (`friendlyName`) to a short row label, a one-line subject, a natural card title, an optional summary, a verbatim command block where applicable, and humanized key/value fields (capped on the main surface with a count of omitted fields). A test-only mock screen (`?approval=offer`) shows the offered-action card beside the command one; the Go formatter mirrors these words so a lock screen and the inbox agree.
2. **Desktop and phone parity (`ApprovalBody`).** Both `DecisionCard` (`web/src/thread.tsx`) and `MAllow` (`web/src/phone.tsx`) render `ApprovalBody`, showing readable wrapped prose (with an inline expand toggle for long values rather than silent mid-line clipping), monospace blocks for commands/paths/code, and the same collapsible `Details` toggle used by `EffectBody` for the raw tool name, full path/host, and raw JSON payload. The judge's note and the "Outside sandbox" badge (V0.tool-approval-judge) are read through `formatApproval` (web/src/approval.ts) and drawn by the same body above the summary on both fronts, so that change's signals survive the rewrite.
3. **Inbox rows and push notifications.** `web/src/rows.ts` (`rowState`, `rowMeta`), the phone peek sheet (`rowDetail`), and `internal/front/notify.go` (`AttentionDetail`) use the same readable action labels and subjects so inbox rows and lock-screen pushes never expose raw `mcp__` identifiers. The phone push table in `design/mobile/README.md` §4 shows the new words, and an approval card's prose and paths can be selected on the phone as a message can.
