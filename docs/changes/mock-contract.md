# V0.mock-contract: the web mock's command effects are checked against a real host

→ V0.24 (the state shape checked against a real host), V0.login-poll-one-host, V0.client-per-host, issue #457.

The layout test runs against `web/src/mock.ts`, a second fyrd in memory, and each of its commands sets the thread's attention by hand. Only the shape of the host's state was checked against a real host, so the mock could drift from what the host does: a login that started already "waiting" hid that the page never followed a running login (V0.login-poll-one-host). The mock stays (the layout test needs a host it can shape: long titles, 40 hosts, a failed deploy), and what it does for each command is now recorded from a real one.

(1) **The host's record.** `TestCommandEffectsFixture` (`internal/engine`) runs the owner's commands on a real engine with the fake agent and writes `web/test/fixtures/command-effects.json`, as `TestStateContractFixture` writes `host-state.json`: for each command the thread as the host sent it before, its projects, its attention then (state, section, group, word), what the command's own upsert showed and, for a command that starts work, every attention its upserts showed until that work ended. Commands: mark seen, mark unseen, pin, unpin, settle (also a pinned thread), unsettle, snooze, unsnooze, archive, unarchive, set project, project archive, project unarchive; snooze, archive and settle of a thread the owner has not read and the mark's undo; answer a question; run a Run card. The attentions are read from the stream as a client reads it (by rev), not from the thread after the reply: an answer shows Seen until the agent takes it, and how long that is depends on the machine. Ids, digests, session ids, the folder and revs are made stable; times keep their order, a second apart. `TestProviderLoginFixture` (`internal/provider`) writes `provider-login.json`: a folder account's login before, right after `provider.login` and once the CLI printed its link (the fake CLI waits for a file, so the first read is never late).

(2) **The mock held to it.** `web/test/mock-contract.test.ts` seeds the mock with the same thread and projects (`seed`, a mock-only method), runs the same command, and asserts the same attention in the mock's pushes, on node's mock timers; and the mock's `provider.login` the same three states.

(3) **What it found, fixed in the mock.** An answer read the thread on the host (Seen) and the agent's turn started after; the mock went to Working at once and never showed Seen. A Run the agent asked for left Needs you when pressed on the host, and its end started the agent's turn; the mock kept the thread in Needs you and started no turn. Archive does not read a thread on the host, so Unarchive brings an unread one back Unread; the mock always brought it back read. The host was right in each.

(4) **Regenerate** with `go test ./internal/engine -run TestCommandEffectsFixture` and `go test ./internal/provider -run TestProviderLoginFixture`; a change to the host's effects then shows as a fixture diff and a failing web test until the mock follows.
