# V0.mac-shell: Fyr.app's shell: the agent registered with SMAppService, a menu-bar item, and the page in a native window

→ decision 0037, step (4) without the DMG's CI and signing; amends V0.130's Mac app (a Chrome app window from `install-macos.sh`).

Why: the script install needs a terminal, Homebrew and a dev toolchain, signs ad hoc (so a permission lasts one build), and opens the page in Chrome. Decision 0037 makes Fyr.app the Mac install: the app carries fyrd and registers it itself. This is the shell, built and run locally. Release signing, `mac.yml` and notifications come next.

1. **`macos/`** holds a Swift package (the shell, macOS 13+), `host/fyr-host.c` and `build.sh`. `build.sh` takes `fyr` and `fyrd` from the release the tag `deployable` points at, anonymously, checks them against `SHA256SUMS`, and joins arm64 and amd64 into universal binaries (`--bin DIR` takes local ones). It builds `Fyr.app`, signs every binary with `FYR_SIGN_IDENTITY` (ad hoc without it) and, with `--dmg`, makes `Fyr.dmg`. The bundle id (`fyr.app`), the agent's label (`fyr.agent`), the data folder, the log and fyrd's flags are variables, so a test install runs beside the real one.
2. **The agent** is `Contents/Library/LaunchAgents/fyr.agent.plist`, registered with `SMAppService.agent` at the app's start (no admin rights; listed in Login Items). Its first process is `fyr-host`, which macOS ties permissions to. It runs `Resources/fyr` (the launcher) with `-seed Resources/fyrd`, so a new install needs no copy, and the self-update into `builds/` is unchanged. `fyr-host` expands `~/` in its arguments, makes the data folder, writes to `~/Library/Logs/fyr.log`, and gives the agents the PATH of the owner's login shell (`$SHELL -i -l`, read between markers, 5 s at most), where Homebrew and nvm put git, gh, claude and node.
3. **Taking over a script install.** At its first start the app stops `com.github.meros.fyr` and its old `.update` job, removes their plists and the script's `~/Applications/Fyr.app`, and keeps the data. A registration that macOS reports as enabled while launchd holds no job (an ad hoc build replaced in place) is registered anew.
4. **The window** is a WKWebView on the origin the last one-time link named (`http://fyr.localhost:PORT`). It asks the owner socket for a new link only when that origin answers 401 or does not answer, so opening the window does not mint a session each time. Other origins and `target=_blank` open in the default browser. Size and place are restored. File pickers, `alert`, `confirm` and `prompt` are native sheets. The page runs to the window's top edge under a transparent title bar with no title, whose strip still drags the window. The shell marks the page `html.mac-app` and sets `--mac-titlebar` to the strip's height (0 in full screen). The page's top line (the first banner, else each column) takes a transparent border of that height, so the rail's colour reaches the edge and the logo and controls sit below the traffic lights; the phone layout (a window under 760 px), the full-screen preview and full-screen layers take it as padding. Browsers never set `.mac-app`. Until the page paints, the window shows its `theme-color` (else its background). Closing the window leaves the menu-bar item and drops the Dock icon. ⌘, opens Settings, ⌘R reloads, ⌘W closes, ⌘Q quits the shell (fyrd keeps running).
5. **The menu-bar item:** Open Fyr, Open in Browser (its own one-time link), the agent's state, Pause/Resume (unregister and register; a pause lasts across app starts), Show Log, Quit.
6. **`Fyr --agent register|unregister|status`** does the registration without the window, for scripts and the clean-VM install test.

Found on the way: an ad hoc build replaced in place is killed by launchd (`OS_REASON_CODESIGNING`), because the registration names the old signature. A certificate-signed build replaced in place keeps running, as the spike found. `codesign` finds an identity only on the user's keychain search list: `build.sh` adds `FYR_SIGN_KEYCHAIN` for the signing and restores the list on exit.

Not yet: notifications and the `native-mac` device kind, the dock badge, dropping files on the window, Uninstall in the menu, the DMG built and signed in CI, the update offer for the app.
