# V0.web-review-fixes: the web client's reads, nav, answers and settles are total, decoded and shared by both fronts

A review of the web client found places where a stalled or odd answer from a host, or a layout change, left the screen wrong. All fixed together, each with a test in `web/test`.

1. **Phone Back after a resize.** The popstate listener was added only the first time the phone layout came on; after phone, desktop, phone it was gone. The history is seeded once, the listener is added and removed with the layout (`nav.ts` `seedHistory`, `listenPopState`).
2. **One `request`** (`web/src/http.ts`) for every call to a host: a 30 s timeout (60 s for a command try, 120 s for the AI search; the SSE stream is not a request), the JSON body read once and never thrown on, one `replyError`. `api.ts` has no `fetch` of its own (a test holds this). command, postJson, mutate and presence still never reject. `api.thread`, `api.fullEvent` and `api.profiles` never reject (they were fired and forgotten); `loadEarlier` catches its page.
3. **Decoded reads.** `hostGet` and `getJson` take a decoder: a list endpoint is read with `arr`, an object endpoint with `obj`, so an unparsable body or a literal `null` no longer reaches a screen as `{}` or throws. `api.thread` runs `decodeThread`; events, commands, changes and file patches are decoded.
4. **Omitted lists.** `decodeChanges` and `decodeFilePatch` give `files` and `since.files` (omitempty) their empty value; `decodeThread` decodes each `Change`, `Offer` and `OfferRun` (`updatedAt`, `createdAt`, `phase`, labels). `test/contract-dto.test.ts` removes each optional field in turn for changes, change lists, the guard and leftovers.
5. **One `useAnswers`** (`app-cards.tsx`) for the answer, cancel and allow commands of both fronts, each answering whether the host took it; the payload is built once (`answerArgs`, `allowArgs`). What follows an answer stays per front: the desktop walks on to the next thread that needs the owner (an arrival bar); the phone stays on its thread.
6. **Settle leaves after success on both fronts.** The desktop left the settled thread before the command ran, so a refused settle had already moved on; it now leaves in `.then`, as the phone does. A bulk settle runs `bulkSettle` once and leaves on the ids it returns. `settleRun` is the one toast option of a settle.
7. **Teardown.** The app's effect removes its `visibilitychange` listener and calls the new `api.stop()`, which closes the stream and removes the `pagehide` and `pageshow` listeners. `pageshow` resets the reconnect backoff.
8. **Storage.** `prefs.ts` has `browserStorage()` and `sessionStore()`; the host-rotation effect, `signout.ts` and the app use them instead of their own try blocks. Several rotations at once move the open thread's ref in one `navReplace` (`moveRefAll`) instead of each overwriting the one before.
9. **Load poll.** A `poll()` that started before a reorder's receipt (`patchSlots`) is dropped, so it cannot put the old order back (`web/src/load-feed.ts`).
10. **Settle merged on the desktop too.** The Seen header has the phone's "Settle merged" button, with the same rule (`mergedToSettle`). ⇧E still settles the whole section (the keyboard's sweep); the button settles only what merged.
