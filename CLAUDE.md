# Fyr: rules for agents

- **Desktop and phone stay in sync.** A change to one front (layout, content, a control) goes to the other in the same PR. A difference is allowed only for a stated reason (touch size, no keyboard, no hover), written next to the code that makes it. Share the component where you can (`web/src/row-ui.tsx` is the inbox row of both).
- **Never interrupt the owner** (SPEC U26, V0.no-interrupt). Anything that arrives from the host, an agent or a timer (a question, an approval, a push, a new build, a pushed value) shows beside what the owner is doing and waits. It never takes the focus, unmounts or repurposes the field they type in, changes what their next key does, replaces their text, opens a dialog or reloads the page under them. A dialog or sheet opens only from the owner's own press. When you add something that appears by itself, say in the PR how it behaves while the owner is typing.
- Another session may work in the main checkout: work in a worktree of your own (`git worktree add .claude/worktrees/<name> -b <branch> origin/main`).
- **A change to the spec's change log is a new file, `docs/changes/<name>.md`, cited as `V0.<name>`** (`docs/changes/README.md`). Do not add a row to the table in `docs/SPEC.md` 0.5 and do not pick a `V0.<number>`: that line is what made every PR conflict. A PR title needs no version.
- **A PR's CI runs on the self-hosted Linux runner** (`.github/workflows/pr.yml`, V0.ci-self-hosted): a fork's PR never runs on it, and it has the Nix store and Chrome the gate needs. A push to a PR starts it; Fyr's merge ask waits for its check. When the runner is down, run `scripts/ci-local.sh` after the push instead: it posts the status `local/test`, which counts the same. Only `pr.yml` runs on pull requests, and only on the self-hosted runner; `test.yml` tests and releases every push to main on the same runner.
- **A flaky test you meet is fixed at its root, in its own change** (not retried until green): a sleep that stands in for a wait, a wall-time budget, a race in the code. Before you call a failure a flake, run the test alone and under load (`go test -count=50 -run X` beside a few busy loops); say what you found in `docs/changes/`.
- **The repository is public** (V0.public-repo). Write no quotes of the owner, no names of other private projects, employers, machines or people, and no personal data (usage numbers, paths, accounts) into code, docs, tests or commit messages; use `acme`, `host-a`, `example.com`. A fork's PR never runs on the self-hosted runner: do not approve one there.
